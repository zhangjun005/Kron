## 1. 一句话总结

为 Kron 加上了 **Git 风格的祖先向上扫描**：任意子目录里跑 `kron xxx` 都能找到项目根，
`kron init` 在已存在祖先项目时会拒绝。同时把零散的"找项目根"样板收归到
`commands::require_project_root(&ctx)` 一个 helper，并顺手把 `project_root` 提到 `Ctx` 上。

### 3.3 Ctx 升级（顺手做的收益）

```rust
// 之前
pub struct Ctx {
    pub mode: OutputMode,
    pub verbose: bool,
}

// 之后
pub struct Ctx {
    pub mode: OutputMode,
    pub verbose: bool,
    pub project_root: Option<PathBuf>,  // NEW
}
```

外加：
- `Ctx::resolve()` —— 一次性查找并缓存
- `commands::require_project_root(&ctx)` —— 全项目唯一 helper

**未来回报**：加新子命令时不用再写样板；project_root 在 helper 中可观测/可缓存/可注入 mock。

### 3.4 status / path 半裸用法修复

| 文件 | 之前 | 之后 |
|------|------|------|
| `status.rs` | `let cwd = current_dir()?; let kron_dir = cwd.join("kron-internal")` | `let root = require_project_root(&ctx)?; let kron_dir = root.join(...)` |
| `path.rs` | `cwd.join("kron-internal")`（无守卫） | `find_project_root(cwd).unwrap_or(cwd).join(...)` |

`path` 是定位命令，本身就该支持 ancestor search，不能 fail。

## 4. 踩过的坑（按时间序）

### 4.1 🟢 Ctx 改成非 Copy 的连锁影响

`Ctx` 从 `#[derive(Copy)]` 改成 `#[derive(Clone)]`（因为加了 `Option<PathBuf>`，
`Copy` 不允许）。原本 `Ctx: Copy` 的代码无需 `&` —— 加引用即可，不影响语义。
但 `path.rs` 有一个 `for` 循环里用 `ctx.mode` 的地方——`Ctx` 已经传入引用的版本，无影响。

### 4.2 🔴 误把 Kron 自己的代码仓库 init 了（事故）

`smoke.ps1` 第一版用 `& $exe init --porcelain <path>`，把路径当 clap 参数传了。
**clap 的 `init` 子命令不接受路径参数**，init 必须在 cwd 上跑。

但我**没意识到这个错误**，还在仓库根目录下执行了 init 命令（cwd 默认是 `$PWD`，
当时是 `E:\works\Kron`），意外创建了 `kron-internal/` 和 `KRON/` 目录。

**修复**：`Remove-Item -Recurse -Force kron-internal, KRON`，仓库恢复干净。
`git status` 确认 untracked 已清。

**教训**：
1. 永远先在**临时目录**做 smoke test，不要假设当前 cwd 是干净的
2. PowerShell 的 `Push-Location` 不会自动回退——必须包在 `try/finally` 里（v2 已修）
3. Smoke 脚本里所有 `& $exe` 都应明示 cwd，避免用默认 cwd 跑 init 这种"副作用大"的命令

### 4.3 🔴 编译 4 轮后才通过：brace 错配

PowerShell 的 `-replace` 用 regex 时，`{` `}` 都是元字符，需要 escape 或用 verbatim 匹配。
我用 PS 删 `fn project_root() { ... }` 时，正则没考虑函数的 `}` 后还有 trailing 内容，
导致删过头，函数体残留成孤儿 `Ok(cwd)`。

**4 个文件**（`vertex.rs`、`task.rs`、`config.rs`、`conflict.rs`、`daemon.rs`、
`important.rs`）依次报 `unexpected closing delimiter`。

**修复循环**（每轮）：
1. `cargo check` 报 brace 错配 + 行号
2. 找到错位位置
3. 删孤儿 `Ok(cwd)` 行 + 多余 `}` 
4. 重新 `cargo check`
5. 直到 `Finished`

**浪费了多少时间**：约 30 分钟（4 轮编译 + 诊断）。

**教训**：
1. **不要用 PowerShell 的 `-replace` 做复杂的 Rust 代码结构修改**——`{}` `()` `()` 嵌套太多
2. 用 `StrReplace` 工具时**精确匹配足够长的 old_string**，保留所有 context
3. 删函数时，正则要包括**整个函数体 + 闭合 `}`**——可以多行匹配
4. **真正正确做法是写脚本前先 inspect 整个函数的 start-end 边界**

### 4.4 🟡 双 `?` 短暂 bug

替换 `require_project()?` → `require_project_root(&ctx)?` 后，PowerShell `-replace` 一刀切没考虑
`require_project()` 已经返回 `Result`，所以 `?` 是**解 Result**。

替换后变成 `require_project_root(&ctx)??`——双 `?` 不通过类型检查。

修复：用 PowerShell 把 `??` 全替成 `?`。一次到位。

### 4.5 🟡 task.rs 误删 KronError import

替换 `use crate::error::{KronError, Result};` → `use crate::error::Result;`，因为最初没意识到
task.rs 函数体里有 12 处 `KronError::Cli(...)` 和 `KronError::NotYetImplemented(...)` 引用。

修复：还原为 `{KronError, Result}`。

**教训**：删 import 前必须先 grep 整个文件中该符号的所有使用。

### 4.6 🟡 Read 工具的"行号幽灵"

PowerShell 删完行后，Read 工具显示的还是旧行号（line 80, 81），实际文件已经少了行。
这是 **Read 工具的内部缓存/快照机制** —— 它按 `limit + offset` 取，而不是真实解析当前文件。

**教训**：修改文件后用 `Get-Content | Select-Object` 或 `cat -n` 验证，而不是 Read 工具。

## 7. 经验教训汇总（按重要性）

### 🔴 高优先级

1. **永远不要假设 cwd 是干净的**——smoke test 先 `Push-Location $tempdir` 再跑命令
2. **结构性代码修改不要用 PowerShell `-replace`**——改用专用工具（StrReplace 等）做精确替换
3. **删 import 前必须 grep** 该符号的使用点（task.rs 误删 KronError 案例）
4. **删除函数前先确认函数体边界**——多行 grep 找 start/end，再删

### 🟡 中优先级

5. **加新公共字段到 struct 时检查所有 derives**——`Copy` 不允许 `Option<T: !Copy>`，
   改成 `Clone` 可能有连锁影响
6. **smoke test 的副作用命令（init）必须包 try/finally**——保证 `Pop-Location`
7. **Read 工具显示行号有时滞后**——大改后用 `cat -n` 验证

### 🟢 低优先级（提醒）

8. **设计文档要包含潜在架构问题清单**——本次提前发现 P-B（Ctx 缺字段）和 P-C
   （error msg 与代码不一致），省了一笔返工
9. **Git 风格的契约是好默认**——本次完全抄了 Git 的 `find_git_dir()` 行为：
   向上遍历到根 / 找不到报错 / 拒绝嵌套。**清晰的参照对象**比"凭空设计"少 70% 思考
10. **"`Ctx` 不该缺 `project_root`"是早就该发现的洞**——`Ctx` 是命令共享上下文，
    而"项目根"是最基础的共享状态。**第一版设计就该有它**

# 07 · 实施路线图（Kron Roadmap）

> 状态：草案 v1（2026-09-05）
> 适用范围：本文档定义 Kron 从零到 v1.0 发布的**实施节奏、任务分解、验收标准、关键里程碑**。
> 读者：开发者本人、可能的合作开发者、AI 编程助手（用于理解上下文优先级）。
> 前置阅读：[00-总览与架构.md](./00-总览与架构.md)、[plan.md](../../plan.md)

## 1. 路线图总览

### 1.1 一句话总结

**7 个 Phase，10 周交付，每个 Phase 都有可演示的产物**。不走瀑布，不画大饼——每个阶段都能在终端里跑出真东西。

### 1.2 Phase 总览

| Phase | 时长 | 核心交付物 | 用户价值 | 可演示？ |
|-------|------|-----------|---------|---------|
| **P0** 脚手架 | 2 天 | Rust workspace + Tauri 工程 + CI | 编译能跑 | ✅ `cargo build` 通过 |
| **P1** 双源 CLI | 1 周 | `kron init` / `status` / `task add` 等 | 能用 CLI 管 task | ✅ 真实项目跑一遍 |
| **P2** 守护进程 | 2 周 | `kron-daemon` + notify + 同步引擎 | 自动同步，零手动 | ✅ 5 分钟内自动 sync |
| **P3** GUI 最小集 | 2 周 | Tauri 界面 + 项目树 + task 看板 | 鼠标能点 | ✅ 双击打开 MD |
| **P4** CLI + Vertex | 1 周 | `kron vertex` / `task move` 等 | 完整操作能力 | ✅ 所有命令都跑通 |
| **P5** AI 易读层 | 1 周 | `.kron-context/` + `kron context` | AI 能完整理解项目 | ✅ AI 准确率达预期 |
| **P6** 打磨 + 打包 | 1 周 | 双主题 + 托盘 + zip + 文档 | 可发布 | ✅ 安装包能装 |

**总计：~10 周（一名全职开发者）**

### 1.3 阶段依赖图

```
   P0 脚手架
    │
    ▼
   P1 双源 CLI  ←─────── 核心：打通"读 MD + 写 JSON"链路
    │
    ├──► P2 守护进程 ──┐
    │                  │  并行
    │                  ▼
    │                P3 GUI 最小集 ──┐
    │                                │  串行（GUI 依赖 daemon IPC）
    │                                ▼
    ├────────────────────────► P4 CLI + Vertex（与 P3 并行）
    │
    ▼
   P5 AI 易读层（依赖 P1-P4 全部产出）
    │
    ▼
   P6 打磨 + 打包
```

**关键路径**：P0 → P1 → P2 → P3 → P6（GUI 路线）
**次要路径**：P0 → P1 → P4 → P5 → P6（CLI 路线）

P3 和 P4 **可并行**（互不依赖；GUI 通过 `kron` CLI 间接调用 P4 的能力）。

### 1.4 优先级与 MVP 边界

**MVP（最小可行产品）= P0 + P1 + P2**

> 即"只用守护进程 + CLI，不用 GUI"，就能解决 80% 的核心问题：
> - 自动同步重要文件 ✅
> - AI 通过 CLI 读写 task ✅
> - 冲突可检测可解决 ✅

GUI 是 **锦上添花**，不是必须。如果时间紧，**砍 P3-P4 也要保 P0-P2 + P5**。

### 1.5 命名约定

| 类型 | 命名 | 说明 |
|------|------|------|
| **Phase** | P0-P6 | 大阶段，每阶段 1-2 周 |
| **里程碑** | M1-M7 | Phase 内的关键节点，必须达到 |
| **任务** | T-N.M | Phase N 的第 M 个任务 |
| **验收标准** | AC-N.M | Phase N 第 M 项的可验证标准 |

### 4.3 关键命令（守护进程 + 冲突）

```bash
kron daemon start               # 启动守护进程
kron daemon start --foreground  # 前台模式（调试）
kron daemon status --json       # 查看状态
kron daemon stop                # 优雅停机

kron conflict list --json       # 列出所有冲突
kron conflict show <id> --json  # 查看冲突详情（结构化 diff）
kron conflict resolve <id> --use project   # 用项目版
kron conflict resolve <id> --use internal  # 用 Kron 内部版
kron conflict resolve <id> --ignore        # 忽略冲突
kron ready --json               # 哨兵：能否继续工作
```

## 10. 风险清单与应对

| # | 风险 | 概率 | 影响 | 应对 |
|---|------|------|------|------|
| **R1** | `notify` 在 Windows 上的事件丢失 | 中 | 中 | § 4 防抖 + 5 分钟扫描兜底 |

| **R3** | 守护进程内存泄漏 | 低 | 中 | 24h soak test（M3 后跑一次）|
| **R4** | Tauri 打包失败（Windows 签名）| 中 | 高 | 跳过代码签名（个人项目），用户接受 SmartScreen 警告 |
| **R5** | MD 解析器对复杂 markdown 处理不当 | 中 | 低 | v1 限制 task MD 只用基础 markdown |
| **R6** | AI 不读 .kron-context/ | 低 | 高 | P5 用真实 AI 跑测试，验证可读性 |
| **R7** | 单人开发进度拖延 | 高 | 中 | 砍 P3-P4，保 P0-P2-P5（见 1.4 MVP 边界）|
| **R8** | 软链接在某些环境下失效 | 中 | 低 | 已有 fallback（复制模式，见 00 § 6.7）|
| **R9** | Rust 学习曲线（首次项目）| 中 | 中 | 优先用熟悉的 crate，不追新 |
| **R10** | Git ref 推导 vertex 关系性能差 | 低 | 中 | v1 缓存 vertices.json，5 分钟重建 |

## 11. 验收总则

### 11.1 CI/CD 配置（贯穿所有 Phase）

**GitHub Actions 工作流**：

```yaml
name: CI
on: [push, pull_request]
jobs:
  rust:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo build --workspace --all-targets
      - run: cargo test --workspace
      - run: cargo clippy --workspace -- -D warnings
      - run: cargo fmt --check
      - run: cargo tarpaulin --workspace --out Xml
        # 覆盖率门槛（按阶段递增）
        # P1: 70% / P2: 75% / P3-P4: 70% / P5-P6: 75%
  
  frontend:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
      - run: pnpm install
      - run: pnpm lint
      - run: pnpm build
      - run: pnpm test
```

## 附录 B：北极星指标（North Star）

- P6 → 用户能"装上用"

任何 Phase 砍掉都不影响这个指标的可达性（只是体验不同）。

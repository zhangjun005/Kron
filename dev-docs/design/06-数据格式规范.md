# 06 数据格式规范（实施级）

> **本文档定位**：实施级规范。01-数据模型.md 定义 Rust 类型；本文档定义**每个文件的精确格式**（字节级）、**解析器的硬性要求**、**容错边界**、**向后兼容策略**。
> 状态：v1 锁定（2026-09-05）
> 读者：实现者（CLI、守护进程、GUI 全部共享）
> 前置阅读：[01-数据模型.md](./01-数据模型.md)、[03-双源同步机制.md](./03-双源同步机制.md)

---

## 0. 规范总览

| # | 文件 | 权威源 | 解析方向 | 解析时机 |
|---|------|--------|---------|---------|
| 1 | `KRON/VERTEX/<name>/description.md` | ⭐ 权威 | 读 | 启动 / 文件变化 |
| 2 | `KRON/VERTEX/<name>/tasks.md` | ⭐ 权威 | 读 + 写回 | 任何 task 操作 |
| 3 | `KRON/VERTEX/<name>/_meta.json` | ⭐ 权威 | 读 + 写 | 守护进程维护 |
| 4 | `KRON/important/<relpath>` | ⭐ 权威（双源同步） | 读 | 启动 / 文件变化 |
| 5 | `kron-internal/config.json` | ⭐ 权威 | 读 + 写 | CLI / GUI |
| 6 | `kron-internal/vertices.json` | ⭐ 权威（汇总索引） | 读 + 写 | 守护进程 |
| 7 | `kron-internal/states/<vertex>.json` | ⭐ 权威（task 状态） | 读 + 写 | 任何 task 状态变更 |
| 8 | `kron-internal/tags/tasks.json` | ⭐ 权威（标签） | 读 + 写 | task 标签变更 |
| 9 | `kron-internal/conflicts/<id>.json` | ⭐ 权威 | 读 + 写 | 冲突检测时 |
| 10 | `KRON/.kron-context/*.md` | 派生（可丢） | 只写 | 守护进程 |
| 11 | `KRON/.kron-context/README.md` | 模板 | 只写 | 首次创建 |

**关键原则**：
- ⭐ 权威源文件 = 必须严格按格式；解析失败 → 退出码 1（不可恢复）
- 派生文件 = 解析失败可重建，不影响业务

## 1. `tasks.md` 格式（核心，最复杂）

### 1.1 文件结构（字节级）

```
UTF-8 编码，LF 或 CRLF 行结尾（统一为 LF 存储）
首行 H1：  "# Tasks — <vertex name>"
随后：空行
然后：每个 task 一个 H2："## [task_<id>] <title>"
再下：H3 子节（## 背景 / 目标 / 实现方案 / 备注，只解析固定 4 个）
其中：H3 内容是 Markdown 自由文本
解析器：仅识别 H1 / H2 / H3 三级标题 + 固定元数据行
```

### 1.2 元数据行（task 头部可识别行）

**位置**：H2 标题下、H3 之前。**最多 6 行**，**顺序固定**。

```
## [task_001] 实现登录功能
state: doing
priority: high
labels: auth, p1
depends_on: task_002, task_005
created: 2026-09-04T10:00:00+08:00
updated: 2026-09-05T09:30:00+08:00

### 背景
...
```

**每个字段的精确格式**：

| 字段 | 必需 | 格式 | 解析失败行为 |
|------|------|------|------------|
| `state` | ✅ | `todo` / `doing` / `done` / `back` / `blocked`（小写） | 退出码 1（损坏） |
| `priority` | ❌ | `low` / `medium` / `high` / `urgent` | 缺失 → `medium` |
| `labels` | ❌ | 逗号分隔，每个 `[a-z0-9_-]+`，1-32 字符 | 空 → `[]` |
| `depends_on` | ❌ | `task_<id>` 列表，逗号分隔 | 空 → `[]` |
| `created` | ✅ | RFC3339（带时区） | 退出码 1 |
| `updated` | ✅ | RFC3339 | 退出码 1 |

### 1.3 H3 子节（自由文本）

**固定 4 个 H3 子节**（可任意顺序，但必须存在）：

```
### 背景        ← Background（为什么做）
### 目标        ← Goal（验收标准）
### 实现方案    ← Approach（技术选型）
### 备注        ← Notes（杂项）
```

**解析规则**：
- H3 内容直到下一个 H2/H3/文件结尾
- 内部支持任意 Markdown（GFM 子集）
- **解析器只关心存在性**，不解析内容
- **写回时保持 H3 内容原样**（包括空内容）

### 1.4 解析器硬性要求

**容错边界**：

| 情况 | 行为 |
|------|------|
| 文件不存在 | 视为空 vertex（无 task） |
| 找不到 H1 | 报错退出码 1 |
| H2 格式不符 `[task_xxx]` | **跳过该 H2**，记录 warning |
| 同一 task_id 出现两次 | **保留第一个**，warning |
| 元数据行缺失必需字段 | 用默认值（`created/updated` 用文件 mtime） |
| 元数据行格式错误 | **保留行原文**，warning，继续 |
| H3 子节缺失 | 视为空字符串 |
| H3 子节顺序乱 | 写回时规范化（H3 必须按"背景→目标→实现方案→备注"） |

**不可恢复错误**（退出码 1）：
- 文件不是 UTF-8
- 行长度超过 10000 字符（防 DOS）
- H2 标题超过 200 字符
- 文件大小超过 10 MB

### 1.5 写回规范（"保持原格式"原则）

**关键**：tasks.md 是**人类维护**的文件，Kron 不能格式化破坏。

**写回规则**：
1. **保持原有 H3 子节顺序**（如果用户写的是"目标→背景→备注"，写回时保持）
2. **保持原有空行风格**（连续空行/单空行/无空行都不动）
3. **只修改元数据行的值**（如 `state: todo` → `state: doing`）
4. **新增 task**追加到文件末尾，H3 模板：
   ```
   ## [task_XXX] 新任务标题
   state: todo
   priority: medium
   created: <RFC3339>
   updated: <RFC3339>
   
   ### 背景
   
   ### 目标
   
   ### 实现方案
   
   ### 备注
   
   ```
5. **删除 task**：直接移除整个 H2 块（从 H2 标题到下一个 H2 之前的空行）

### 1.6 完整示例（标准 tasks.md）

```markdown
# Tasks — backend

## [task_001] 实现登录功能
state: doing
priority: high
labels: auth, p1
depends_on: task_002
created: 2026-09-04T10:00:00+08:00
updated: 2026-09-05T09:30:00+08:00

### 背景
用户反馈登录体验差

### 目标
3 秒内完成 OAuth 流程

### 实现方案
Google OAuth2 provider

### 备注
测试账号已申请

## [task_002] 设计数据库表结构
state: todo
priority: medium
created: 2026-09-04T10:00:00+08:00
updated: 2026-09-04T10:00:00+08:00

### 背景
...

### 目标
...

### 实现方案
...

### 备注
...
```

## 2. `description.md` 格式

### 2.1 文件结构

```
UTF-8，LF
首行 H1："# <vertex name>"
随后：任意 Markdown（GFM 子集）
```

### 2.2 解析规则

**只识别**：
- H1 标题（解析 vertex 名）
- 文件内容整体视为 `description: string`（不解析内部结构）

**容错**：
- 文件缺失 → 视为空 description
- 非 UTF-8 → 退出码 1
- 无 H1 → 自动插入 `# <vertex_name>`（name 来自目录名）

### 2.3 写回规范

- 整体替换文件（除 H1 行外的内容 = `description` 字段值）
- 保留 LF 行结尾

## 3. `_meta.json` 格式

### 3.1 完整 schema

```json
{
  "schema_version": 1,
  "vertex": "backend",
  "branch": "main",
  "git_commits": ["a1b2c3d", "e4f5g6h"],
  "created_at": "2026-09-04T10:00:00+08:00",
  "last_synced_at": "2026-09-05T18:00:00+08:00"
}
```

### 3.2 字段约束

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `schema_version` | u32 | ✅ | 当前 1；v2 升级时做迁移 |
| `vertex` | string | ✅ | vertex 目录名（小写、snake_case、≤32 字符） |
| `branch` | string \| null | ✅ | Git 分支名（绑定点） |
| `git_commits` | string[] | ✅ | 绑定点对应的 commit SHA 列表（按时间正序） |
| `created_at` | RFC3339 | ✅ | vertex 创建时间 |
| `last_synced_at` | RFC3339 | ✅ | 最近一次双源同步时间 |

### 3.3 维护规则

- **只由守护进程写**，CLI/GUI 不直接修改
- 文件大小 ≤ 1 KB
- 写时序：写临时文件 + fsync + rename（原子）

## 4. `vertices.json` 格式（汇总索引）

### 4.1 schema

```json
{
  "schema_version": 1,
  "vertices": [
    {
      "name": "backend",
      "branch": "main",
      "task_count": { "todo": 3, "doing": 1, "done": 5, "back": 0, "blocked": 0 },
      "created_at": "2026-09-04T10:00:00+08:00",
      "last_seen_at": "2026-09-05T18:00:00+08:00"
    }
  ]
}
```

### 4.2 维护规则

- 由守护进程在扫描 `KRON/VERTEX/` 时增量更新
- 与 `KRON/VERTEX/<n>/_meta.json` **可能短暂不一致**（守护进程 5 分钟内收敛）
- 单源：仅 `kron-internal/vertices.json`，**无项目内镜像**

## 5. `states/<vertex>.json` 格式

### 5.1 schema

```json
{
  "schema_version": 1,
  "vertex": "backend",
  "tasks": {
    "task_001": {
      "state": "doing",
      "priority": "high",
      "labels": ["auth", "p1"],
      "depends_on": ["task_002"],
      "created_at": "2026-09-04T10:00:00+08:00",
      "updated_at": "2026-09-05T09:30:00+08:00",
      "history": [
        { "state": "todo", "at": "2026-09-04T10:00:00+08:00" },
        { "state": "doing", "at": "2026-09-05T09:30:00+08:00" }
      ]
    }
  }
}
```

### 5.2 维护规则

- 每次 task 状态变更时写整个文件（先写临时 + rename）
- `history` 限制最多 50 条
- `updated_at` 与 tasks.md 中的 `updated` 行必须一致（守护进程同步）

## 6. `tags/tasks.json` 格式

### 6.1 schema

```json
{
  "schema_version": 1,
  "by_label": {
    "auth": ["backend:task_001", "backend:task_005"],
    "p1": ["backend:task_001"]
  },
  "by_vertex": {
    "backend": ["task_001", "task_002", "task_005"]
  }
}
```

### 6.2 维护规则

- 守护进程从各 vertex 的 tasks.md 聚合
- 索引结构，不存 task 详情（详情查 states）

## 7. `conflicts/<id>.json` 格式

### 7.1 schema

```json
{
  "schema_version": 1,
  "id": "c-abc123",
  "path": "KRON/important/notes.md",
  "type": "both_modified",
  "detected_at": "2026-09-05T18:00:00+08:00",
  "internal": {
    "mtime": "2026-09-05T17:55:00+08:00",
    "size": 1024,
    "checksum": "sha256:abc..."
  },
  "project": {
    "mtime": "2026-09-05T17:58:00+08:00",
    "size": 1100,
    "checksum": "sha256:def..."
  },
  "status": "pending",
  "resolution": null
}
```

### 7.2 状态机

`pending` → `resolved` / `ignored`（终态）

### 7.3 保留策略

- 已解决冲突保留 30 天（`conflicts/archive/`），过期删除
- 同一路径 24h 内重复冲突 → 去重（不创建新记录）

## 9. `.kron-context/*.md` 格式（派生文件）

### 9.1 共同约束

- UTF-8、LF
- 文件大小 ≤ 1 MB（超出截断）
- 文件头必须包含 Kron 自动生成标记：

```markdown
<!-- kron-generated: 2026-09-05T18:00:00+08:00 -->
<!-- DO NOT EDIT. Run 'kron context --regenerate' to refresh. -->

(后续内容)
```

### 9.2 `git/recent-commits.md` 格式

```markdown
<!-- kron-generated: ... -->

# Recent Commits

最近 100 次 commit，按时间倒序。

| SHA | Date | Author | Subject | Files |
|-----|------|--------|---------|-------|
| a1b2c3d | 2026-09-05 | alice | OAuth login | 5 |
| ...
```

### 9.3 `git/branch-summary.md` 格式

```markdown
<!-- kron-generated: ... -->

# Branch Summary

**Current branch**: `feat/oauth`
**Main branch**: `main`
**Ahead**: 3 commits
**Behind**: 0 commits

## Ahead (3)
- a1b2c3d OAuth login
- e4f5g6h Add DB migration
- i7j8k9l Fix tests

## Behind (0)
(none)
```

### 9.4 `code/structure.md` 格式

```markdown
<!-- kron-generated: ... -->

# Project Structure

深度：3（可配置）

```
my-project/
├── src/
│   ├── main.rs
│   └── lib.rs
├── tests/
└── KRON/
    └── VERTEX/
```

(跳过: node_modules/, target/, .git/)
```

### 9.5 `README.md`（context 索引）

```markdown
<!-- kron-generated: ... -->

# .kron-context/

Kron 自动生成的事实型结构快照（**仅包含可重现的事实，不包含语义理解**）。

## 范围边界

本目录**不包含**：
- 项目是干啥的（看项目根 README.md）
- 架构设计（看 KRON/important/architecture.md）
- 代码约定（看 KRON/important/conventions.md）
- "为什么这么实现"——没有，请读源码

本目录**包含**：
- 最近 commit 列表（git log）
- 当前分支与主分支对比
- 项目目录结构树

## 文件清单

| 文件 | 内容 | 生成时机 |
|------|------|---------|
| `git/recent-commits.md` | 最近 100 次 commit | 新 commit 时 |
| `git/branch-summary.md` | 当前分支 vs main | HEAD 变化时 |
| `code/structure.md` | 目录树（深度 3） | 文件增删时 |
| `README.md` | 本文件 | 手动维护 |

## 重新生成

```bash
kron context              # 增量
kron context --regenerate # 全量
kron context --list       # 看状态
```
```

## 10. 通用规范

### 10.1 行结尾

- **存储统一 LF**（写入时统一转换）
- 读取时**接受 CRLF / LF / CR**，统一转 LF 处理
- tasks.md 等用户文件**保留原行结尾**（写回时不强行转换）

### 10.2 字符编码

- **统一 UTF-8**（无 BOM）
- 读取时检测 BOM：有 BOM → 退出码 1（损坏）
- 文件大小超过 10 MB → 退出码 1

### 10.3 时间格式

- 内部存储统一 RFC3339（带时区）
- 显示给用户用本地时区 + 相对表达（"5 分钟前"）
- 不支持 Unix 时间戳字符串

### 10.4 ID 格式

| 类型 | 格式 | 长度 | 示例 |
|------|------|------|------|
| `task_<id>` | 6 位 hex（小写） | 6 | `task_001`, `task_abc123` |
| `vertex_<id>` | 同 task 或 human name | — | `backend` |
| `c-<id>` | 8 位 base36 | 8 | `c-abc12345` |
| `t-<id>` | 同 task_xxx | 6 | `t-001`, `t-abc123` |

**冲突处理**：冲突时数字递增（task_001 → task_002），不行则用 4 位随机后缀

### 10.5 文件锁

- 所有写操作必须加文件锁（详见 03-双源同步 § 3）
- 锁等待超时：1 秒
- 失败重试：3 次，指数退避

## 11. 向后兼容策略

### 11.1 schema 版本升级流程

```
v1 文件 → 检测到 schema_version 字段 → 升级路径 → v2 文件
```

**规则**：
1. 解析器**必须**忽略未知字段（不报错）
2. 缺失字段有默认值
3. 新字段必须可选
4. 旧解析器读新文件：忽略未知字段，用默认值
5. 新解析器读旧文件：缺失字段用默认值

### 11.2 BREAKING 变更处理

何时算 BREAKING：
- 删除字段
- 改字段类型
- 改枚举值（移除旧值）

**BREAKING 时必须**：
1. 升级 `schema_version`
2. 提供迁移脚本（`kron migrate --from v1 --to v2`）
3. 在 CHANGELOG 标记
4. 保留 v1 解析支持 ≥ 1 个 major 版本

### 11.3 文件格式迁移示例

**v1 → v2（假设添加 `priority` 字段）**：
```
v2 文件有 priority，v1 解析器忽略 → OK
v1 文件无 priority，v2 解析器用默认值 medium → OK
```

**v1 → v2（假设 state 新增 'archived' 值）**：
```
v2 文件有 state="archived"，v1 解析器遇到未知值 → 报错（不可恢复）
→ 必须先升级解析器
```

## 12. 错误检测与报告

### 12.1 启动时健康检查

```bash
$ kron doctor   # v1 内置健康检查命令
```

| 检查项 | 失败时 |
|--------|--------|
| 所有 ⭐ 权威源文件可读 | 退出码 6 |
| 所有 ⭐ 权威源文件 JSON 合法 | 退出码 1 |
| 所有 ⭐ 权威源文件 schema_version 匹配 | 尝试迁移；失败退出码 1 |
| 守护进程 socket 可连 | 退出码 10（仅 daemon 命令） |
| Git 仓库状态 | warning（不阻止） |

### 12.2 运行时错误恢复

- **派生文件丢失**：自动重建（不报错）
- **权威源文件损坏**：进入只读模式，所有写命令失败（退出码 1 + stderr 建议 `kron doctor`）
- **权限错误**：stderr 提示用户（退出码 9）

## 13. 测试要求（实施时）

### 13.1 解析器单元测试

- 每个文件格式必须有 ≥ 10 个 fixture
- 覆盖：合法文件、缺字段、未知字段、错误枚举、错误时间格式、非 UTF-8、超大文件
- 双向测试：解析 → 修改 → 写回 → 再解析（往返一致性）

### 13.2 并发测试

- 多进程同时写同一文件：锁正常工作
- 守护进程 + CLI 同时写：CLI 失败退出码 7
- 断电/崩溃恢复：临时文件清理

### 13.3 兼容性测试

- v1 解析器读 v2 文件：✓
- v2 解析器读 v1 文件：✓
- 跨 OS（Windows / macOS / Linux）：行结尾、路径分隔符

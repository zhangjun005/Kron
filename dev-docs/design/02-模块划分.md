# Kron 模块划分与扩展性设计

> 本文档定义 Rust workspace 结构、每个 crate 的职责边界、模块间通信机制、Trait 接口契约。
> 对应需求：dev-docs/requirements.md
> 对应架构：dev-docs/design/00-总览与架构.md
> 对应数据模型：dev-docs/design/01-数据模型.md

---

## 1. 设计原则

Kron 的扩展性建立在一组硬性约束之上，**任何违反这些约束的 PR 必须被拒绝**：

| # | 原则 | 检验方法 |
|---|------|---------|
| 1 | `kron-core` 零外部依赖 | `cargo metadata` 看不到任何外部 crate（仅 std） |
| 2 | 模块间通信只有两条路：trait 调用（命令）或事件总线（通知）| 禁止 `use` 其它业务模块的内部类型 |
| 3 | 新增功能不改已有模块 | git diff 只涉及 `kron-core` 加 trait + 新模块 + 入口注册 |
| 4 | Git 集成严格降级 | `kron-git` 不在依赖图核心位置，**无监听接口** |
| 5 | 所有 Trait 实现可热替换 | `AppHandles::default().with_xxx(...)` 切换 |

### 3.2 核心约束

| 模块 | 可依赖 | 不可依赖 |
|------|--------|---------|
| `kron-core` | std | 任何外部 crate |
| `kron-storage` | `kron-core` | 其它任何 |
| `kron-git` | `kron-core` | 其它任何 |
| `kron-sync` | `kron-core` | 其它任何 |
| `kron-context` | `kron-core` + `kron-git` | 其它任何 |
| `kron-cli` | 所有上面 | 任何前端 |
| `kron-gui` | 所有上面 | Tauri 之外的 GUI 框架 |
| `kron-daemon` | 所有上面 | 任何前端 |

**关键性质**：去掉任何入口（`kron-cli` / `kron-gui` / `kron-daemon`）都不会影响其它入口或业务模块。

## 4. 通信机制：Trait + 事件总线

### 4.1 三层通信模型

```
┌─────────────────────────────────────────────────┐
│ Layer 3: AppHandles（依赖注入容器）               │
│  - 构造期组装所有 Trait 实现                      │
│  - 静态可见，不可热替换                           │
└─────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────┐
│ Layer 2: 事件总线（KronEvent）                    │
│  - 跨模块异步通知                                │
│  - 1:N 广播，多订阅者                            │
└─────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────┐
│ Layer 1: Trait 调用（直接函数调用）               │
│  - 命令式操作：读、写、执行                       │
│  - 1:1 同步调用                                  │
└─────────────────────────────────────────────────┘
```

### 4.2 模块自洽性规则

**每个业务模块（`kron-storage` / `kron-git` / `kron-sync` / `kron-context`）对外只暴露 3 样东西**：

1. **一个主结构体**（如 `FsStorage`）—— 该模块的入口
2. **实现一个或多个 Trait** —— 由 `kron-core` 定义
3. **可能订阅事件** —— 通过构造函数传入 `EventBus` 引用

模块内部的所有细节（辅助函数、私有结构、子模块）对其它模块完全不可见。

```rust
// kron-storage/src/lib.rs
pub use fs_storage::FsStorage;
pub use notify_watcher::FsWatcher;

// 内部细节不导出
mod fs_storage;
mod atomic;
mod symlink;
mod notify_watcher;
```

## 5. AppHandles 依赖注入容器

### 5.1 类型定义

```rust
// kron-core/src/handles.rs

use std::sync::Arc;
use crate::ports::{
    storage::StorageBackend,
    repo::{ProjectRepo, VertexRepo, TaskStateRepo, TagRepo, ImportantRepo},
    git::GitInfo,
    sync::SyncStrategy,
    parser::TaskParser,
    context::ContextGenerator,
    notifier::Notifier,
};
use crate::events::KronEventBus;

#[derive(Clone)]
pub struct AppHandles {
    // === 存储 ===
    pub storage: Arc<dyn StorageBackend>,
    pub project_repo: Arc<dyn ProjectRepo>,
    pub vertex_repo: Arc<dyn VertexRepo>,
    pub task_state_repo: Arc<dyn TaskStateRepo>,
    pub tag_repo: Arc<dyn TagRepo>,
    pub important_repo: Arc<dyn ImportantRepo>,

    // === Git ===
    pub git: Arc<dyn GitInfo>,

    // === 同步 ===
    pub sync: Arc<dyn SyncStrategy>,

    // === 解析与生成 ===
    pub parser: Arc<dyn TaskParser>,
    pub context: Arc<dyn ContextGenerator>,

    // === 通信 ===
    pub events: Arc<KronEventBus>,

    // === 扩展点 ===
    pub notifiers: Vec<Arc<dyn Notifier>>,
}

impl AppHandles {
    /// 默认实现（生产环境）
    pub fn default_for_project(project_path: &Path) -> Result<Self, KronError> {
        let events = Arc::new(KronEventBus::default());
        let storage = Arc::new(FsStorage::new(project_path.to_path_buf()));
        let git = Arc::new(GitCli::new(project_path.to_path_buf()));

        Ok(Self {
            storage: storage.clone() as Arc<dyn StorageBackend>,
            project_repo: Arc::new(FileProjectRepo::new(storage.clone())),
            vertex_repo: Arc::new(FileVertexRepo::new(storage.clone())),
            task_state_repo: Arc::new(FileTaskStateRepo::new(storage.clone())),
            tag_repo: Arc::new(FileTagRepo::new(storage.clone())),
            important_repo: Arc::new(FileImportantRepo::new(storage.clone())),
            git: git.clone() as Arc<dyn GitInfo>,
            sync: Arc::new(SimpleSyncStrategy::new(storage.clone())),
            parser: Arc::new(MarkdownTaskParser::new()),
            context: Arc::new(KronContextGenerator::new(storage.clone(), git)),
            events,
            notifiers: vec![],
        })
    }

    /// 链式注册 Notifier（扩展点）
    pub fn with_notifier(mut self, n: Arc<dyn Notifier>) -> Self {
        self.notifiers.push(n);
        self
    }

    /// 链式替换任何字段（测试或高级用法）
    pub fn with_sync(mut self, s: Arc<dyn SyncStrategy>) -> Self {
        self.sync = s;
        self
    }
}
```

### 5.2 入口组装

```rust
// kron-cli/src/app.rs

pub fn build_cli_handles(project_path: &Path) -> Result<AppHandles, KronError> {
    let mut handles = AppHandles::default_for_project(project_path)?;

    // 注册 CLI 特定的 notifier（如日志输出）
    handles = handles.with_notifier(Arc::new(CliLogNotifier::new()));

    Ok(handles)
}

// kron-daemon/src/app.rs

pub fn build_daemon_handles(project_path: &Path) -> Result<AppHandles, KronError> {
    let mut handles = AppHandles::default_for_project(project_path)?;

    // 注册守护进程特定的 notifier
    handles = handles
        .with_notifier(Arc::new(DaemonTrayNotifier::new()))
        .with_notifier(Arc::new(DaemonAutoSyncNotifier::new(
            handles.storage.clone(),
            handles.events.clone(),
        )));

    Ok(handles)
}
```

## 6. Trait 接口契约

### 6.1 StorageBackend（存储抽象）

**位置**：`kron-core/src/ports/storage.rs`

**目的**：抽象文件系统读写，使 storage 后端可替换（测试用 in-memory、生产用 FsStorage）。

```rust
// kron-core/src/ports/storage.rs

pub trait StorageBackend: Send + Sync {
    /// 读取整个文件为字节
    fn read(&self, path: &Path) -> Result<Vec<u8>, StorageError>;

    /// 读取并解析为 UTF-8 字符串
    fn read_string(&self, path: &Path) -> Result<String, StorageError> {
        let bytes = self.read(path)?;
        String::from_utf8(bytes).map_err(|e| StorageError::NotUtf8(e.to_string()))
    }

    /// 原子写入（先写 .tmp 再 rename）
    fn write(&self, path: &Path, data: &[u8]) -> Result<(), StorageError>;

    /// 原子写入字符串
    fn write_string(&self, path: &Path, content: &str) -> Result<(), StorageError> {
        self.write(path, content.as_bytes())
    }

    /// 删除文件（不存在不报错）
    fn remove(&self, path: &Path) -> Result<(), StorageError>;

    /// 文件/目录是否存在
    fn exists(&self, path: &Path) -> bool;

    /// 是否为文件
    fn is_file(&self, path: &Path) -> bool;

    /// 是否为目录
    fn is_dir(&self, path: &Path) -> bool;

    /// 创建目录（含父目录）
    fn create_dir_all(&self, path: &Path) -> Result<(), StorageError>;

    /// 读取修改时间
    fn mtime(&self, path: &Path) -> Result<SystemTime, StorageError>;

    /// 列出目录条目
    fn list(&self, path: &Path) -> Result<Vec<PathBuf>, StorageError>;

    /// 计算文件 hash（MD5）
    fn hash(&self, path: &Path) -> Result<String, StorageError>;
}

#[derive(thiserror::Error, Debug)]
pub enum StorageError {
    #[error("IO error: {0}")]
    Io(#[from] std::io::Error),
    #[error("not a utf-8 file: {0}")]
    NotUtf8(String),
    #[error("path not found: {0}")]
    NotFound(PathBuf),
    #[error("permission denied: {0}")]
    PermissionDenied(PathBuf),
}
```

**实现方**：
- `kron-storage::FsStorage`（生产）

**约束**：
- 所有方法必须线程安全（`Send + Sync`）
- `write()` 必须原子（先写 `.tmp` 再 `rename`，避免半写状态）
- `read_*()` 不存在的文件返回 `StorageError::NotFound`

### 6.2 Repo 系列（CRUD 抽象）

**位置**：`kron-core/src/ports/repo.rs`

**目的**：抽象数据访问层，使数据存储方式可替换。

```rust
// kron-core/src/ports/repo.rs

#[async_trait]
pub trait ProjectRepo: Send + Sync {
    async fn load(&self, name: &str) -> Result<Project, RepoError>;
    async fn save(&self, project: &Project) -> Result<(), RepoError>;
    async fn list_all(&self) -> Result<Vec<ProjectSummary>, RepoError>;
    async fn delete(&self, name: &str) -> Result<(), RepoError>;
}

#[async_trait]
pub trait VertexRepo: Send + Sync {
    /// 加载单个 vertex 的 _meta.json
    async fn load_meta(&self, project_path: &Path, vertex_name: &str)
        -> Result<VertexMeta, RepoError>;

    /// 保存单个 vertex 的 _meta.json
    async fn save_meta(&self, project_path: &Path, meta: &VertexMeta)
        -> Result<(), RepoError>;

    /// 加载汇总索引
    async fn load_index(&self, project_path: &Path)
        -> Result<VerticesIndex, RepoError>;

    /// 更新汇总索引（添加/删除 vertex 后调用）
    async fn save_index(&self, project_path: &Path, index: &VerticesIndex)
        -> Result<(), RepoError>;

    /// 列出项目内所有 vertex
    async fn list_vertices(&self, project_path: &Path)
        -> Result<Vec<VertexMeta>, RepoError>;

    /// 删除 vertex（包括 tasks.md 和 description.md）
    async fn delete(&self, project_path: &Path, vertex_name: &str)
        -> Result<(), RepoError>;
}

#[async_trait]
pub trait TaskStateRepo: Send + Sync {
    async fn load(&self, project_path: &Path, vertex: &str)
        -> Result<VertexTaskStates, RepoError>;

    async fn save(&self, project_path: &Path, states: &VertexTaskStates)
        -> Result<(), RepoError>;

    async fn set_state(
        &self,
        project_path: &Path,
        vertex: &str,
        task_id: &str,
        new_state: TaskState,
    ) -> Result<VertexTaskStates, RepoError>;
}

#[async_trait]
pub trait TagRepo: Send + Sync {
    async fn load(&self, project_path: &Path) -> Result<GlobalTagsIndex, RepoError>;
    async fn save(&self, project_path: &Path, index: &GlobalTagsIndex)
        -> Result<(), RepoError>;
}

#[async_trait]
pub trait ImportantRepo: Send + Sync {
    async fn load(&self, project_path: &Path) -> Result<ImportantFilesIndex, RepoError>;
    async fn save(&self, project_path: &Path, index: &ImportantFilesIndex)
        -> Result<(), RepoError>;
    async fn add(&self, project_path: &Path, src: &Path)
        -> Result<ImportantFileMeta, RepoError>;
    async fn remove(&self, project_path: &Path, rel_path: &str)
        -> Result<(), RepoError>;
    
    /// 列出当前已索引的文件
    async fn list(&self, project_path: &Path) -> Result<Vec<ImportantFileMeta>, RepoError>;
}
```

**实现方**：
- `kron-storage::FileProjectRepo`（基于 FsStorage）
- `kron-storage::FileVertexRepo`
- 等等...

**注意**：**Repo 不在 `kron-storage`，它在 `kron-storage` 内部**。从外部看，`kron-storage` 暴露的是 `FsStorage`（实现 `StorageBackend`）+ 文件级 Repo 集合。

### 6.3 GitInfo（Git 抽象）

**位置**：`kron-core/src/ports/git.rs`

**目的**：抽象 Git 信息读取，**严格降级**——没有 `subscribe()` 这种监听接口。

```rust
// kron-core/src/ports/git.rs

#[derive(Debug, Clone)]
pub struct HeadInfo {
    pub commit: String,         // 完整 commit hash
    pub branch: Option<String>, // None 表示 detached HEAD
}

#[derive(Debug, Clone)]
pub struct CommitInfo {
    pub hash: String,
    pub short_hash: String,
    pub author: String,
    pub timestamp: DateTime<Utc>,
    pub message: String,
}

pub trait GitInfo: Send + Sync {
    /// 读取当前 HEAD（commit + branch）
    /// 不在 git 仓库或 git 不可用 → Ok(None)
    fn current_head(&self) -> Result<Option<HeadInfo>, GitError>;

    /// 读取最近 N 条 commit
    /// 不在 git 仓库或 git 不可用 → Ok(vec![])
    fn recent_commits(&self, n: usize) -> Result<Vec<CommitInfo>, GitError>;

    /// 从 start_commit 出发反向遍历父提交，
    /// 在 candidates 中找 commit graph 中最近的绑定点
    /// 返回 (候选 BindPoint, 距离 start 的提交数)
    fn find_nearest_bind_point(
        &self,
        start_commit: &str,
        candidates: &[BindPoint],
    ) -> Result<Option<(BindPoint, usize)>, GitError>;

    /// 当前 commit 是否有未提交修改
    fn is_dirty(&self) -> Result<bool, GitError>;
}

#[derive(thiserror::Error, Debug)]
pub enum GitError {
    #[error("git CLI error: {0}")]
    Cli(String),
    #[error("git parse error: {0}")]
    Parse(String),
    #[error("commit not found: {0}")]
    CommitNotFound(String),
}
```

**实现方**：
- `kron-git::GitCli`（生产，调用 `git` 命令行）
- `kron-git::NoopGit`（fallback，所有方法返回 None/空）

**Git 集成的边界（明确列出）**：

❌ **Kron 不做的事**：
- 不监听 `.git/` 任何文件
- 不安装 Git Hooks
- 不在 commit / checkout / merge / pull 时自动操作
- 不感知分支切换
- 不做 Git 可视化
- 不解析 git diff 用于自动推荐 task

✅ **Kron 做的事**（仅这 4 件）：
- `kron vertex create` 时调一次 `current_head()`
- GUI 计算 Vertex 与 commit 对应关系时按需调 `find_nearest_bind_point()`
- `kron context` 生成 git 类文档时按需调 `recent_commits()`
- 所有 git 调用失败时优雅降级（不报错，只是不提供 git 相关信息）

### 6.4 SyncStrategy（同步策略）

**位置**：`kron-core/src/ports/sync.rs`

**目的**：抽象双源同步逻辑，使同步策略可替换。

```rust
// kron-core/src/ports/sync.rs

use crate::model::sync::{FilePair, SyncDirection, ConflictRecord};

#[derive(Debug, Clone)]
pub enum ConflictDecision {
    UseProject,        // 用项目内的版本
    UseInternal,       // 用 Kron 内部版本
    UseBoth(Bytes),    // 都保留（合并）
    Defer,             // 推迟决定
}

#[async_trait]
pub trait SyncStrategy: Send + Sync {
    /// 检测单个文件对是否需要同步
    async fn detect(&self, pair: &FilePair) -> Result<SyncDirection, SyncError>;

    /// 检测整个项目下所有需要同步的文件
    async fn scan_all(&self, project_path: &Path)
        -> Result<Vec<FilePair>, SyncError>;

    /// 执行一次同步操作
    async fn sync(&self, pair: &FilePair) -> Result<(), SyncError>;

    /// 处理冲突（由 AppHandles.sync 调用）
    async fn resolve_conflict(
        &self,
        pair: &FilePair,
        decision: ConflictDecision,
    ) -> Result<(), SyncError>;

    /// 复原：将 Kron 内部版本恢复到项目内
    async fn restore(
        &self,
        project_path: &Path,
        internal_path: &Path,
        target_path: &Path,
    ) -> Result<(), SyncError>;

    /// 备份冲突版本
    async fn backup_conflict(
        &self,
        record: &ConflictRecord,
    ) -> Result<(), SyncError>;
}
```

**实现方**：
- `kron-sync::SimpleSyncStrategy`（基础实现，mtime + hash）

**未来扩展点**：
- `BidirectionalSyncStrategy`：带双向冲突合并
- `CRDTSyncStrategy`：基于 CRDT 的强一致同步（v3+）

### 7.2 总线实现

```rust
// kron-core/src/events/mod.rs

use std::sync::Arc;
use tokio::sync::broadcast;
use crate::events::kron_event::KronEvent;

pub struct KronEventBus {
    sender: broadcast::Sender<KronEvent>,
}

impl Default for KronEventBus {
    fn default() -> Self {
        let (sender, _) = broadcast::channel(1024);
        Self { sender }
    }
}

impl KronEventBus {
    /// 发布事件（所有订阅者都会收到）
    pub fn publish(&self, event: KronEvent) {
        // 忽略错误（无订阅者时不报错）
        let _ = self.sender.send(event);
    }

    /// 订阅
    pub fn subscribe(&self) -> broadcast::Receiver<KronEvent> {
        self.sender.subscribe()
    }
}
```

### 7.3 订阅示例

```rust
// kron-daemon/src/watcher.rs

use kron_core::events::KronEvent;

pub async fn run_watcher(handles: AppHandles) -> Result<(), KronError> {
    let mut receiver = handles.events.subscribe();

    while let Ok(event) = receiver.recv().await {
        match event {
            KronEvent::FileChanged(e) if e.path.starts_with("KRON/VERTEX/") => {
                // 触发 vertex tasks 重新解析
                let project = handles.storage.clone();
                let events = handles.events.clone();
                tokio::spawn(async move {
                    let _ = reparse_vertex_tasks(&project, &e.path, events).await;
                });
            }
            KronEvent::TaskStateChanged(e) => {
                // 同步双源
                let sync = handles.sync.clone();
                let storage = handles.storage.clone();
                tokio::spawn(async move {
                    let _ = sync.sync_task_state(&storage, &e.project, &e.vertex, &e.task_id).await;
                });
            }
            _ => {}
        }
    }
    Ok(())
}
```

## 8. Parser（MD 解析器）位置说明

MD 解析在多个场景都需要（CLI 状态查询、守护进程检测 MD 变化、GUI 详情），单独建 crate 价值不大（解析规则集中在 ~500 行代码）。两种选择：

| 选项 | 优 | 劣 |
|------|----|----|
| **A. 作为 `kron-storage` 的子模块** | 避免新 crate，依赖最少 | 解析与文件 IO 耦合 |
| **B. 单独 `kron-parser` crate** | 严格分层，纯函数式 | 多一个 crate |

**采用方案 A**：`kron-storage/src/md_parser.rs`，实现 `kron_core::ports::parser::TaskParser` trait。理由：解析规则与文件路径强相关（要从 KRON/VERTEX/<name>/tasks.md 读），与 storage 行为天然在一起。

## 11. 错误处理规范

所有模块统一使用 `KronError`：

```rust
// kron-core/src/error.rs

#[derive(thiserror::Error, Debug)]
pub enum KronError {
    #[error("storage error: {0}")]
    Storage(#[from] StorageError),

    #[error("repo error: {0}")]
    Repo(#[from] RepoError),

    #[error("git error: {0}")]
    Git(#[from] GitError),

    #[error("sync error: {0}")]
    Sync(#[from] SyncError),

    #[error("parse error: {0}")]
    Parse(#[from] ParseError),

    #[error("context error: {0}")]
    Context(#[from] ContextError),

    #[error("project not initialized: {0}")]
    ProjectNotInit(String),

    #[error("vertex not found: {0}")]
    VertexNotFound(String),

    #[error("task not found: {0}")]
    TaskNotFound(String),

    #[error("invalid input: {0}")]
    InvalidInput(String),

    #[error("IO error: {0}")]
    Io(#[from] std::io::Error),
}
```

**错误传播原则**：
- 内部模块用细粒度错误（`StorageError` / `GitError` 等）
- 跨模块边界统一转为 `KronError`
- CLI / GUI 层捕获 `KronError` 后格式化输出（CLI 友好文本 / GUI toast）

# Kron 总体设计

> 本文档是 Kron 项目的**第一份设计文档**，面向后续所有详细设计的"路线图 + 总览"。
> 阅读对象：开发者、AI 助手、未来回顾者。
> 详细设计请见同目录下的 `01` ~ `07` 文档。

---

## 1. 一句话定位

**Kron = 一个让个人开发者的"项目代码 + 项目文档 + 项目任务"对 AI 透明可读、对人零学习成本的桌面工具。**

三个关键词：
- **透明可读**：所有数据落盘为纯文本 Markdown，AI 工具零集成即可读写。
- **零学习成本**：用户不需要学 CLI、不需要记快捷键、不需要懂 Git 也能用。
- **桌面工具**：本地优先、便携式分发（zip 解压即用）、不依赖云端。

---

## 2. 设计哲学（贯穿所有模块）

> 这些哲学不是"听起来不错"，而是用于**解决具体设计冲突时的取舍依据**。

| 哲学 | 含义 | 反例（Kron 拒绝做的） |
|------|------|---------------------|
| **做减法** | 只解决一个明确问题，不做"未来可能用得上"的功能 | 不做 priority / due_date / estimate |
| **AI 易读** | 所有数据都以 AI 工具能自然读取的格式存在 | 不做加密、不做二进制存储 |
| **主动权在用户** | 数据怎么写由用户/AI 决定，Kron 只做管家 | 不强制 Vertex 命名规则、不强制 description 结构 |
| **主动权在 Kron** | 自动化机制由 Kron 自己掌控，不依赖外部 | 删除 Git Hooks，守护进程自监听 |
| **简洁优于完美** | 有歧义时选最简单的方案 | 不做版本历史（依赖 Git）、不做云同步（v1） |
| **系统优于自研** | 能让 Windows/Shell/VSCode 做的事就交给它们 | 自定义右键菜单？→ 用系统原生菜单 |

## 3. 系统全景图

### 3.1 三进程结构

```
┌─────────────────────────────────────────────────────────┐
│                      用户视角                              │
│  鼠标点击 / Typora 编辑 / Cursor 修改 MD / Git 操作         │
└─────────────────────────────────────────────────────────┘
        │            │           │            │
        ▼            ▼           ▼            ▼
┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
│  kron.exe  │ │kron-cli.exe│ │ Typora /   │ │  git CLI   │
│  (GUI)     │ │ (CLI)      │ │ VSCode /   │ │ (只读)     │
│            │ │            │ │ Cursor /   │ │            │
│            │ │            │ │ Claude Code│ │            │
└─────┬──────┘ └─────┬──────┘ └─────┬──────┘ └─────┬──────┘
      │              │              │              │
      └──────────────┴──────────────┴──────────────┘
                     │
                     │  所有读写都走文件系统
                     ▼
      ┌──────────────────────────────────────────┐
      │        文件系统（双源 + 软链接）           │
      ├──────────────────────────────────────────┤
      │  D:\code\my-project\                     │
      │  └── KRON/  ────symlink────┐             │
      │                             │             │
      │  D:\Apps\Kron\data\projects\my-project\   │
      │  ├── KRON/                  ◀────────────┘
      │  └── kron-internal/
      │      ├── config.json
      │      ├── states/
      │      ├── tags/
      │      └── important/
      └──────────────────────────────────────────┘
                     ▲
                     │ 文件变化事件
                     │
      ┌──────────────┴───────────────────────────┐
      │      kron-daemon.exe（系统托盘后台进程）    │
      │  ─ 监听所有文件变化                         │
      │  ─ 解析 MD → 更新元数据                    │
      │  ─ 检测冲突 → 触发同步                      │
      │  ─ 增量更新 .kron-context/                │
      │  ─ 定时任务（5 分钟扫描过期）               │
      └──────────────────────────────────────────┘
```

**关键点**：
- 三个进程**对文件系统是平权的**——任何一个修改文件，守护进程都会感知并同步。
- 守护进程是**唯一的自动化中枢**。GUI 不监听、CLI 不监听、它们都是"按需操作"。
- 进程间**不直接通信**——通过文件系统间接协作（简化进程模型，避免 IPC 复杂度）。

### 3.2 双源数据架构

```
┌─────────────────────────────────────────────────────────┐
│  KRON/  ←  项目内（软链接）   AI 友好   人类可读           │
│  ─────────────────────────────────────────              │
│  • README.md                                              │
│  • VERTEX/<name>/                                         │
│    ├── description.md      （自由格式）                   │
│    ├── tasks.md            （极简 task 格式）              │
│    └── _meta.json          （Vertex 绑定点）               │
│  • important/             （用户主动添加的重要文件）        │
│  • .kron-context/         （Kron 自动生成的中间文档）       │
└─────────────────────────────────────────────────────────┘
        ↕  双向同步（任一为最新即可；冲突时提示）
┌─────────────────────────────────────────────────────────┐
│  kron-internal/  ←  Kron 内部权威源                       │
│  ─────────────────────────────────────────                │
│  • config.json            （项目配置 + 路径映射）         │
│  • states/<vertex>.json   （task 状态，5分钟同步）         │
│  • tags/tasks.json        （task tags）                    │
│  • important/<relpath>    （重要文件双源备份）              │
│  • vertices.json          （vertex 列表 + 绑定点汇总）     │
└─────────────────────────────────────────────────────────┘
```

**数据所有权规则**（避免"谁改谁负责"的混乱）：

| 数据类型 | 项目内（KRON/） | Kron 内部（kron-internal/） | 写方 |
|---------|---------------|---------------------------|------|
| Task description / title | ✅ 权威源 | ❌ 不存 | 用户/AI 直接编辑 |
| Vertex description | ✅ 权威源 | ❌ 不存 | 用户/AI 直接编辑 |
| Vertex 绑定点 | `_meta.json` 权威源 | `vertices.json` 镜像 | Kron 自动同步 |
| Task state | ❌ 不存 | ✅ 权威源（`states/*.json`） | GUI 拖拽 / CLI |
| Task tags | `tags:` 行权威源 | 镜像（`tags/tasks.json`） | Kron 解析 + 同步 |
| 重要文件内容 | ✅ 权威源 | ✅ 备份 | 用户编辑 + Kron 同步 |
| .kron-context/ | ✅ 唯一源 | ❌ 不存 | Kron 自动生成 |
| 项目配置 | ❌ 不存 | ✅ 权威源 | CLI / GUI |

### 3.3 跨进程读写模型

```
       用户/AI                 GUI/CLI                 守护进程
        │                       │                       │
        │  编辑 MD（直接写）      │                       │
        ├──────────────────────►│ 文件系统 ─────────────►│ 监听器
        │                       │                       │
        │                       │                       │ 解析 + 校验
        │                       │                       │
        │                       │                       │ 写 kron-internal/
        │                       │                       ├──────────────►
        │                       │                       │
        │                       │  GUI 自动刷新         ◄┤ IPC（可选）
        │                       ◄───────────────────────┤
        │
        │  GUI 拖拽 task 改 state│
        ├──────────────────────►│                       │
        │                       │ 写内存                │
        │                       │ （5 分钟后定时落盘）    │
        │                       ├──────────────────────►│
        │                       │                       │ 写 states/*.json
```

**核心约定**：用户/AI 是**内容的权威源**，Kron 是**元数据的权威源**。

## 4. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 桌面框架 | **Tauri 2.x** | 轻量、跨平台（v1 只做 Windows）、Rust 后端、HTML/CSS 前端 |
| 前端框架 | **React 18 + TypeScript** | 生态成熟、类型安全、AI 工具友好 |
| 样式 | **Tailwind CSS** | 双主题支持简洁、自定义成本低 |
| 状态管理 | **Zustand** | 极简、无 boilerplate，比 Redux 轻得多 |
| 构建 | **Vite** | 与 Tauri 集成最好 |
| Rust 异步运行时 | **Tokio** | Tauri 内置依赖、notify crate 也用它 |
| 文件监听 | **`notify` crate** | 跨平台、事件驱动、Windows 上走 ReadDirectoryChangesW |
| Git 集成 | **直接调用 `git` CLI** | 不引入 git2 crate（体积大），只需读取 commit graph 和 ref |
| 序列化 | **`serde_json`** + **`serde_yaml`** | JSON 用于内部元数据，YAML 用于 `_meta.json`（更人类可读） |
| 时间 | **`chrono`** | 统一 UTC 存储、本地展示 |
| 日志 | **`tracing`** + `tracing-subscriber` | 结构化日志、按等级过滤、按文件轮转 |
| 软链接 | **`std::os::windows::fs::symlink_dir`** | 标准库、零依赖 |
| 系统调用 | **`opener` crate** 或直接 `ShellExecuteW` | 打开外部应用 |

**故意不选**：
- ❌ `git2` crate（体积大 + 不必要，我们只读不写）
- ❌ `tauri-plugin-sql` 等数据库插件（Kron v1 不需要数据库）
- ❌ `diesel` / `sqlx`（同上）
- ❌ 任何 AI SDK（Kron 不做 AI 辅助）

## 6. 关键设计决策（需求文档已定 + 本文档明确化）

> 这一节用于消除需求文档中**有意保留的歧义**，给出明确方案。

### 6.1 数据 Schema（关键字段）

#### `kron-internal/config.json`
```json
{
  "project_name": "my-project",
  "project_path": "D:\\code\\my-project",
  "kron_data_path": "D:\\Apps\\Kron\\data\\projects\\my-project",
  "created_at": "2026-09-05T10:00:00Z",
  "kron_version": "0.1.0",
  "settings": {
    "conflict_threshold_minutes": 5,
    "auto_resolve": "prompt",   // prompt | latest | manual
    "context_refresh_minutes": 5
  }
}
```

#### `KRON/VERTEX/<name>/_meta.json`
```json
{
  "name": "开发",
  "created_at": "2026-09-04T10:00:00Z",
  "bind_points": [
    {
      "commit": "abc1234",
      "branch": "feature/login",
      "created_at": "2026-09-04T10:00:00Z"
    }
  ]
}
```
> **绑定点 = 一个 Vertex 在某个 commit 上的"起点"**。允许多个 = 同一 Vertex 可在不同 commit 重新启动。

#### `kron-internal/states/<vertex>.json`
```json
{
  "vertex": "开发",
  "states": {
    "task_001": "in_progress",
    "task_002": "todo",
    "task_003": "done"
  },
  "updated_at": "2026-09-04T20:00:00Z"
}
```
> **5 分钟同步**：GUI 拖拽后，先写内存，5 分钟后由守护进程（定时任务）落盘。
> **冲突策略**：直接编辑 MD 删除 task → 守护进程下次扫描时清理对应 state 条目。

#### `kron-internal/tags/tasks.json`
```json
{
  "task_001": ["#后端", "#认证", "#feature"],
  "task_002": ["#后端", "#数据库"]
}
```
> 从 MD 中的 `tags:` 行解析得到。MD 是权威源，Kron 内部是镜像（用于快速过滤）。

#### `kron-internal/vertices.json`（与各 vertex `_meta.json` 的关系）
- **权威源**：`KRON/VERTEX/<name>/_meta.json`（每个 vertex 一份）
- `kron-internal/vertices.json` 是**汇总索引**，由守护进程自动维护：
```json
{
  "vertices": [
    {"name": "开发", "bind_points_count": 2, "latest_bind": "abc1234"},
    {"name": "重构", "bind_points_count": 1, "latest_bind": "def5678"}
  ]
}
```
> 用于 GUI 启动时快速列出所有 Vertex（避免扫描每个 `_meta.json`）。

### 6.2 Task MD 格式（最终版）

> 需求文档已有详细规范，此处仅确认与 JSON 字段的对应关系。

| 字段 | MD 中位置 | Kron 内部存储 |
|------|---------|------------|
| `id` | `## [task_001]` 标题前缀 | 解析时提取，**不单独存储** |
| `title` | `## [task_001] 实现登录功能` | 解析时提取，**不单独存储** |
| `description` | 二级标题（`### 背景` / `### 目标` / 自由内容） | **不存储**，运行时解析 |
| `tags` | 单行 `tags: #后端 #认证` | `kron-internal/tags/tasks.json` |
| `state` | **不存在于 MD** | `kron-internal/states/<vertex>.json` |
| `created_at` | 不存在 | Kron 在首次解析时记录，存内存 |
| `updated_at` | 不存在 | Kron 解析时计算 = 文件 mtime |
| `started_at` | 不存在 | Kron 内部（状态转 In Progress 时记录） |
| `completed_at` | 不存在 | Kron 内部（状态转 Done 时记录） |

**MD 格式硬约束**（Kron 解析器严格校验）：
- `## [task_XXX]` 中 `XXX` 必须为数字（可前导零）
- `tags:` 行必须是 task 块内**单行**
- task 块之间必须用 `---` 分隔（或下一个 `## [task_...]` 开始）

**软约束**（不强制，用户可自由编辑）：
- `### 背景` / `### 目标` / `### 实现方案` / `### 备注` 四个二级标题
- description 的语言和长度

### 6.3 守护进程监听规则

**监听路径**（精确到文件，避免噪音）：
```
{project_path}/KRON/VERTEX/*/*.md        ← task MD 变化
{project_path}/KRON/VERTEX/*/_meta.json  ← Vertex 绑定点变化
{project_path}/KRON/important/**          ← 重要文件变化
{project_path}/.git/HEAD                  ← 分支切换（轻量）
{project_path}/.git/refs/heads/*          ← 新 commit
{project_path}/.git/index                 ← Git 状态变化
```

**事件合并**（debounce）：
- 同一文件 200ms 内的多次修改视为一次事件
- 批量编辑（如 AI 工具一次修改多个 task）通过短时间窗（1s）合并

**事件分类**：
| 事件类型 | 触发源 | 处理 |
|---------|--------|------|
| `MdChanged` | MD 文件被修改 | 解析 → 更新 tags 镜像 → 触发 GUI 刷新 |
| `ImportantChanged` | 重要文件被修改 | 计算 mtime → 判断场景 A/B/C/D/E → 执行同步 |
| `GitRefChanged` | HEAD/refs 变化 | 触发 vertex 关系重算 |
| `GitIndexChanged` | index 变化 | 触发 `from-git-diff` 推荐缓存刷新 |

**定时任务**：
- 每 5 分钟：扫描 `.kron-context/` 过期文档 → 增量更新
- 每 5 分钟：GUI 内存中的 task state 落盘到 `states/*.json`
- 每 1 小时：检查 `config.json` 的 `updated_at` 与磁盘 mtime 是否一致（完整性自检）

### 6.4 GUI 架构原则

**铁律 1：左键单击 = 选中，左键双击 = 用系统默认应用打开**
- 完全照搬 Windows 资源管理器
- 不实现自定义右键菜单（让 Windows 系统处理"打开方式"）
- Kron 内部操作放在**右侧详情栏**（选中文件后显示）

**铁律 2：Kron 不内置 MD 编辑器**
- 编辑 MD → 双击打开 Typora / VSCode / Cursor（取决于系统默认）
- Kron 只展示 task 列表、状态看板等"结构化视图"

**铁律 3：拖拽 = 状态变化**
- task 拖到不同列 = state 变化
- 仅写内存，不修改 MD
- 5 分钟后由守护进程落盘

**主界面布局**（v1 最小集）：
```
┌─────────────────────────────────────────────────────────────┐
│  [项目切换器]    [Vertex 选择]   [搜索]    [设置]   [关于]   │
├──────────┬──────────────────────────────────┬───────────────┤
│ 项目树    │  主视图（默认: Task 看板）         │  详情/操作栏   │
│          │                                  │               │
│          │   Todo    In Progress    Done     │   选中文件时    │
│          │   ─────   ────────────   ─────    │   显示元信息    │
│          │   □ ...   □ ...         ✓ ...   │   + Kron 操作   │
│          │                                  │               │
│          │                                  │               │
└──────────┴──────────────────────────────────┴───────────────┘
```

### 6.5 CLI 设计原则

> 需求文档已明确清单，本文档明确**架构约束**：

1. **CLI = 单文件 bin，无外部状态**：每次执行从文件系统重建状态，进程退出后不残留。
2. **AI 友好输出**：stdout 是结构化的（JSON 可选 `--format json`），stderr 是诊断信息。
3. **退出码**：`0` 成功 / `1` 通用错误 / `2` 格式错误 / `3` 冲突未解决 / `4` 权限不足。
4. **不与守护进程通信**：CLI 写文件后由守护进程异步处理（与用户直接编辑 MD 行为一致）。

### 6.6 错误处理与日志

**错误分类**（`kron-core::error::KronError`）：
```rust
pub enum KronError {
    // I/O 错误
    IoError(std::io::Error),
    PathNotFound(PathBuf),
    PermissionDenied(PathBuf),

    // 解析错误
    MdParseError { file: PathBuf, line: usize, msg: String },
    InvalidTaskId(String),
    DuplicateTaskId(String, PathBuf),

    // 同步错误
    ConflictDetected { file: PathBuf, internal_mtime: SystemTime, project_mtime: SystemTime },
    BackupFailed(PathBuf, String),

    // Git 错误
    GitNotInstalled,
    NotAGitRepo(PathBuf),
    CommitNotFound(String),

    // 守护进程错误
    AlreadyRunning,
    IpcFailed(String),

    // 配置错误
    ConfigCorrupted(PathBuf),
    InvalidConfig(String),
}
```

**日志策略**：
- 默认 level = `info`
- 文件：`<kron_data>/global/logs/kron-{date}.log`，按天轮转，保留 30 天
- 关键操作（kron init、restore、conflict resolve）单独 `tracing::info!`
- 守护进程后台事件 `tracing::debug!`（默认隐藏）

### 6.7 安全与权限

**v1 安全模型（极简）**：
- 不引入用户/认证（单机单用户）
- 文件操作使用当前用户权限
- 软链接创建需要权限（落地策略：失败时回退到"复制"模式，提示用户）
- `ShellExecute` 失败时 → 提示用户并 fallback 到 `cmd /c start "" "<path>"`

**不做**（v1）：
- 加密本地数据
- 权限检查（任何能访问文件系统的人 = 数据所有者）
- 远程访问接口

## 8. 风险与未决问题

### 来自需求文档的"待讨论问题"（影响实现细节）
1. Kron 内部数据是否加密？→ **建议不做**（v1 个人本地工具，无加密必要）
2. 云盘自动备份 UI？→ **不做 UI**，用户用云盘客户端自动同步 `D:\Apps\Kron\data\` 即可
3. Vertex 删除时是否需要"保留 task"选项？→ **不做**（避免孤儿 task）
4. 守护进程扫描频率？→ **默认 5 分钟**，可在 `config.toml` 调整
5. 首次启动是否引导设置默认 MD 应用？→ **不做**，用户自己设置系统默认应用
6. ShellExecute 失败时的 fallback？→ `cmd /c start "" "<path>"`
7. Vertex 默认值？→ **不预设**，用户自行创建

### 设计中需要进一步验证的
- 守护进程在 Windows 上的开机自启动策略（计划用 `taskschd.msc`）
- 大文件（>100MB）在 important/ 下的同步性能（计划：先 hash 对比，相同则跳过）
- 二进制文件（图片、PDF）的"双源备份"语义（计划：完全一致复制）
- 软链接在跨盘符场景下的兼容性（已用 `symlink_dir` 标准库方案）
- Tauri WebView2 在老 Windows（如 Win7）的兼容（v1 不考虑，文档明确仅支持 Win10+）

## 10. 一段话总结

Kron 是一个**进程简单、数据简单、交互简单**的桌面工具。它把复杂留给三个进程（GUI/CLI/Daemon）和两个数据源（项目内 MD + Kron 内部 JSON），把简单留给用户——**打开就能用，关闭不用管，AI 直接读得到**。

它的差异化不在功能多，而在**克制**：不做的事比做的事更重要。

## B. 新功能提案

### F1 自定义 intent 正文模板（body-only）

现状：`kron add`（CLI）用 `parser.IntentBodyTemplateCN`，MCP `kron_add` 用
`parser.IntentBodyTemplate`（英文）；模板硬编码，两处措辞不统一。

提案：

- 约定文件 **`.kron/templates/intent-body.md`**（UTF-8，正文 only；不存在 = 当前默认）。
- 读取放在 `internal/parser`（bottom layer），CLI/MCP 共用；frontmatter 仍由代码生成。
- 支持最小占位符：`{{slug}}`、`{{title}}`（`title` 为 slug 末段 + dash→space），不引入模板引擎。
- `kron_add` / MCP `kron_add` 在 `body` 为空时使用该模板；显式传入 body 时忽略模板。
- node/leaf 暂时共用一份；后续可扩展 `.kron/templates/intent-body-node.md`。
- 不新增 `config.toml` 字段（遵守零配置原则；文件存在性即开关）。
- VSIX 新建立表单不需要读模板：body 留空提交由后端填充；表单占位文案提示"留空使用项目模板"。
- 测试：模板存在/缺失、占位符替换、CLI/MCP 一致性；文档同步 `intent-structure.md` §三。

待拍板：文件路径/文件名是否用 `intent-body.md`；占位符是否只要 slug/title。

**2026-10-29 澄清（方向修正中）**：用户指出该模板"主要是给 AI 用的，例如目前在 GUI 里
预填充展示的那种"。对照现状：

- 后端 `kron add` / MCP `kron_add` 在 body 为空时用硬编码模板（`internal/parser/template.go`）；
- VSIX 新建表单 body 是空的，只显示硬编码 placeholder（`webview/src/App.tsx`），项目无法控制；
- Wails GUI 只读，没有新建/编辑/预填充；
- MCP 没有把模板暴露给 AI 的通道。

因此"给 AI 用的模板"至少还差两步：**把模板暴露给客户端/Agent**（MCP resource 或工具），
以及**客户端新建时真正预填内容**（VSIX form 取模板填入 textarea，而不是 placeholder）。
**2026-10-29 实施（v1，已落地）**：范围收敛为"只注入 AI 可见文本"，不做后端兜底/校验。
文件 `.kron/templates/intent-body.md`（缺失或空 = 不注入）。注入点：

1. `initialize` 的 `ServerOptions.Instructions`（`## Project intent body template` 段）；
2. `kron_add` / `kron_update` 的 tool description；
3. `kron-implement` prompt 渲染内容。

实现位于 `cmd/kron/serve-mcp/intent_template.go`；测试 `intent_template_test.go`。
注意：tool description/instructions 在 server 启动时读取一次（改模板需重启 MCP 子进程）；
prompt 每次调用实时读取。后端 `kron_add` 空 body 的硬编码 scaffold **不变**。

待确认：模板是"正文骨架"还是"给 AI 的写作指令"；AI 通过 MCP resource 读取还是后端只在
`kron_add` 时兜底；"GUI 预填充"具体指 VS Code Webview 表单还是 Wails GUI 的展示。

### F2 锚点扫描配置 JSON（per-language）——2026-10-30 已实施

现状（实施前参考）：

- Go 侧 `parser.ScanAnchors` → `WalkSourceFiles` 扫描**所有非二进制文件**（跳过
  `.git/.kron/node_modules/vendor/dist/bin/target/.idea/.vscode`），**不按语言/扩展名过滤**；
  锚点语法是"行内任意位置出现 `@kron:intent` + 空白 + slug"，与注释前缀无关。
- 因此 `.tsx/.jsx/.vue/.svelte` 今天已经被 lint/density 扫描；JSX `{/* @kron:intent x */}`、
  Vue `<!-- @kron:intent x -->` 都能匹配。
- 差异在**编辑器侧**：`kron.lspLanguages` 默认列表没有 `typescriptreact`/`javascriptreact`/
  `vue`/`svelte`/`astro`，所以这些文件没有 hover/definition（下划线仍由 VSIX 自己扫描，
  是 language-agnostic 的）。`anchorMenu.ts` 的插入注释前缀对 react 用 `//`，在 JSX 内部
  （`return (` 之后）插入会破坏语法；目前只适合放在组件声明上方。

提案：项目级文件 **`.kron/anchor-scan.json`**（不存在 = 当前全量行为）：

```jsonc
{
  "version": 1,
  "include": ["src/**", "apps/**"],          // 可选；默认全部
  "exclude": ["**/*.min.ts", "generated/**"],// 可选
  "languages": {
    "go":              { "extensions": [".go"] },
    "typescriptreact": { "extensions": [".tsx", ".jsx"],
                         "comment": { "line": "//", "block": ["{/*", "*/}"] } },
    "vue":             { "extensions": [".vue"],
                         "comment": { "line": "//", "block": ["<!--", "-->"] } }
  }
}
```

- Go：`WalkSourceFiles`/`ScanAnchors` 按 include/exclude + extensions 过滤；无文件 = 原行为。
- VSIX：扩展 host 直接读取该 JSON（项目配置，不 import `internal/`），用来：
  1) 生成 LSP `documentSelector` 语言列表（替代/补充 `kron.lspLanguages`）；
  2) 锚点插入时选 `comment.line` / `comment.block`；
  3) 下划线/快速创建的语言范围。
- GUI 不需要。
- 不放进 `config.toml`（避免改配置 schema）；不改变锚点语法本身。
- 测试：无文件默认兼容、include/exclude、扩展名过滤、VSIX 语言列表/插入前缀。

待拍板：文件名 `anchor-scan.json`；是否允许 include/exclude；`comment` 是否只用于"插入"。

### F3 前端文件（tsx/jsx/vue/svelte）扫描现状与补齐——2026-10-30 已实施

实施前结论：

- **仓库扫描（lint / density / LSP document 扫描）已经覆盖前端**：raw text 匹配 marker，
  与注释语法无关。
- **VSIX 下划线**也覆盖任意非 `.kron` 文件（`findAnchors` language-agnostic）。
- **缺口**：LSP hover/definition 的语言选择器来自 `kron.lspLanguages`，默认没有
  react/vue/svelte/astro → 这些文件 Ctrl+click/hover 不工作；`anchorMenu` 插入前缀对
  JSX 内部不安全。

补齐提案（可并入 F2）：

1. `DEFAULT_LSP_LANGUAGES` 增加 `typescriptreact`/`javascriptreact`/`vue`/`svelte`/`astro`；
2. 插入锚点时按语言 + 行上下文选前缀：模块作用域 `//`；JSX children 内部用 `{/* ... */}`；
   Vue/Svelte 模板内用 `<!-- ... -->`（基于 F2 的 `comment` 配置或内置映射）；
3. 允许 F2 JSON 覆盖默认语言→扩展/注释映射；
4. 文档补充"前端锚点推荐放在组件/函数声明上方"的约定。

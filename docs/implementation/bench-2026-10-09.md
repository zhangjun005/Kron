## 3. OPT-1 缓存落地（2026-10-13）

### 3.1 实现

新增 `cmd/kron/serve-mcp/cache.go`：

```go
var cache   = make(map[string]*intentCache) // keyed by abs(root)
var sfGroup singleflight  // 避免并发重复加载

type intentCache struct {
    intents []*model.Intent
    snapshot intentSnapshot // 每个 intent .md 的路径、大小、mtime
}

func LoadAllCached(ctx, root) ([]*model.Intent, error)
func InvalidateCache(root string)
```

- **singleflight**：同 stdio 进程内多个 handler 并发调用，只执行一次 `LoadAll`
- **metadata snapshot invalidation**：每次 cache 命中前只遍历 `.kron/intents/**/*.md` 的路径、大小和 mtime；任一 intent 的新增、删除、重命名或编辑都会重载。不会扫描项目源码；写操作（add / update / delete / restore）后仍显式 `InvalidateCache`
- **写后失效**：kron_add / kron_update / kron_delete / kron_restore 成功返回前调用 `InvalidateCache(root)`
- **不**：不下沉到 `internal/store`（铁律 #5）

### 3.2 缓存效果（`TestCacheEffect`，2026-10-13 实测）

冷路径（首次调用）：同 `TestBenchReport` 结果（~50ms/500 intents）。
热路径（同会话第 2 次调用）：

| 工具 | 500 intents 冷 | 500 intents 热 | 加速比 |
|---|---:|---:|---:|
| `kron_stale` | 59.1ms | 0.17ms | **346x** |
| `kron_impact` | 57.9ms | 0.35ms | **166x** |
| `kron_intent_density` | 57.2ms | 1.0ms | **56x** |
| `kron_list` | 65.2ms | 4.4ms | **15x** |
| `kron_lint` | 88.7ms | 81.3ms | 1.1x |

**`kron_lint` 几乎无效**：主要时间在 `parser.ScanAnchors`（全 source tree walk），不在 `LoadAll`。

**AI 工具典型场景**：一次请求调 3-5 个 `kron_*` 工具，首次 ~50ms，后续每次 <1ms。

### 3.3 验证命令

```bash
# 单次调用耗时表（冷启动）
go test -v -run "TestBenchReport$" -timeout 10m ./cmd/kron/serve-mcp/

# 缓存冷/热路径对比（推荐）
go test -v -run "TestCacheEffect$" -timeout 10m ./cmd/kron/serve-mcp/

# 完整 benchmark（更慢，按需）
go test -bench=BenchmarkTool -benchtime=3x -run=^$ -timeout 30m ./cmd/kron/serve-mcp/
```

## 4. 下次再跑怎么对比

- `TestBenchReport`：单次调用耗时，冷启动（每次 fresh session）。对比 baseline +20% / +50% 阈值
- `TestCacheEffect`：同会话热路径。对比热路径 >2x 退化意味着缓存失效逻辑坏了

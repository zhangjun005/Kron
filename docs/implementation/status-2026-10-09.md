## 4. 协议层"禁止手搓"清单（仅 MCP / LSP）

按 `docs/abstractDesign/architecture.md` §〇 铁律 #5 + 各 SDK 锁定 RFC：

| 协议 | 必用 SDK | 禁止手搓 |
|---|---|---|
| **MCP** | `github.com/modelcontextprotocol/go-sdk v1.1.0` | JSON-RPC 帧 / initialize 握手 / tools/list / tools/call / 错误码 |
| **LSP** | `go.lsp.dev/protocol v3.17+` | Content-Length 帧 / JSON-RPC 解码 / initialize 能力协商 / 文档同步 |

**WHY（仅对 MCP / LSP）**：

- 协议手搓 = 与官方 spec 漂移 = 客户端兼容性事故
- 官方 SDK 已覆盖 spec 边界条件（capability negotiation / cancel handler / progress notification）
- 维护成本：spec 演进时 SDK 跟；手搓代码**永远**落后

**CLI 不在本约束内**（user 拍板 2026-10-09）：

- CLI 是**本地进程 argv 解析**（`os.Args[1]`），**不是** wire protocol
- 现状：`cmd/kron/cli/cli.go` 用 stdlib（`switch os.Args[1]`），**不**引 cobra
- 加新 subcommand / flag 走 [`docs/process/cli-flag.md`](../process/cli-flag.md) 流程
- 若将来某天 CLI 需要"协议化"（如 daemon 化 / remote 调用），**那时**再讨论 SDK 选型；当前**不**预设

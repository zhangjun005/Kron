# 业务定义

> 本文档描述 Kron 对外提供哪些核心能力，以及能力之间的依赖关系。
> 文档措辞偏建议而非规定，旨在对齐认知，不约束具体实现。

---

## 目标

把"为什么这样做"沉淀为仓库内的第一公民，让人类和 AI Agent 都能按需检索、共同维护。

---

## 核心业务

### 2.1 意图本体（Intent Entity）

意图条目是整个系统的原子单位。

**建议这样设计：**
- 每个意图对应一个 `.kron/intents/*.md` 文件
- 文件包含 Markdown 正文 + YAML frontmatter
- 代码侧可通过 `// @kron:intent <slug>` 锚点指向该意图

**为什么需要这件事：**
意图不沉淀就会丢失。丢了之后，下一任接手者（包括 AI）只能反推——推错了就埋坑。这个问题在 `requirements.md` §2 和 `article.md` 有更详细的论证。

**与其他业务的关系：**
是 2.2 和 2.3 的基础。没有条目，关系无对象，协作无内容。

---

### 2.2 意图关系（Intent Relations）

意图之间需要表达两类关系：纵向层级和横向依赖。

#### 纵向：目录即树

**建议这样设计：**
意图文件的物理路径即逻辑层级。文件夹是模块，文件是叶子意图。**不建议用 frontmatter 字段表达层级关系。**

意图的目录结构与源代码目录结构是**独立的两套**，可各自按需组织。具体映射机制（如何建立意图结构与代码结构之间的关联）留到实现阶段再讨论。

理由：
- 目录结构本身就是意图的层级分解，无需额外元数据
- 所有编辑器原生支持文件夹折叠，零学习成本
- AI 生成路径时不会把全局 ID 填错
- GUI 端做目录递归遍历即可生成意图树

#### 横向：相对链接

**建议这样设计：**
跨模块依赖用标准 Markdown 相对链接表达，如 `[@token-bucket](../rate-limit/token-bucket.md)`。代码侧锚点 `// @kron:intent slug` 表达"代码 → 意图"的反向引用。

理由：
- 不装插件时，VSCode / Typora / GitHub 网页端也支持 `Ctrl+单击` 跳转
- AI 读取和生成 Markdown 时天然理解 `[@slug]` 格式
- 代码侧和文档侧共用同一套 Hover + 跳转机制，用户心智一致

**与其他业务的关系：**
纵向层级被 GUI 的树形视图直接消费。横向依赖被 MCP 做范围裁剪时消费。

---

### 2.3 意图协作（Intent Collaboration）

意图写完只是草稿，要被实际消费才算闭环。

**建议这样设计：**
三种对外入口：

- **MCP**：给 AI Agent 提供意图的检索与校验能力（参考 `requirements.md` §3）
- **LSP**：给编辑器提供 Hover 悬停预览 + `Ctrl+单击` 跳转，覆盖代码 / Markdown / 目录上下文（参考 `requirements.md` §5）
- **GUI**：提供意图树浏览与关系图可视化（Phase 2，非 v1 必需）

IDE 交互建议统一为以下三路：

| 触发位置 | 元素形式 | Hover | Ctrl+单击 |
|---|---|---|---|
| 源码 | `// @kron:intent jwt-sliding-window` | 弹出意图摘要 | 跳转打开对应 `.md` |
| 意图 MD（横向） | `[@token-bucket](../rate-limit/token-bucket.md)` | 弹出被依赖意图摘要 | 跳转打开目标 `.md` |
| 意图 MD（纵向父级） | `[@auth](README.md)` 或自动推导 | 弹出父模块背景与范围边界 | 跳转打开父级 README.md |

**为什么需要这件事：**
AI 需要在写代码前后取意图（LSP hover 让人类就地核验），GUI 提供结构化浏览。意图不消费，就只是另一个没人看的文档。

**与其他业务的关系：**
消费 2.1 和 2.2 的产物。协作中发现的问题（意图过期 / 假设失效）建议回流到 2.1 触发更新。

---

## 业务关系总览

```
2.1 意图本体
│
├─ 产出条目 ──► 2.2 意图关系
│                纵向: 目录即树（路径 = 层级）
│                横向: [@slug] 相对链接
│
└─ 产出条目 ──► 2.3 意图协作
                 MCP（给 AI） / LSP（给编辑器） / GUI（Phase 2）
```

---

## 不做的事

以下内容不在当前业务范围内，不建议在 v1 实现：

- **任务追踪**：task 只是意图落地的派生钩子，不是独立业务
- **意图健康度诊断**：过期 / 孤儿 / 冲突检测——`requirements.md` 未明确要求，建议等有实际需求再引入
- **导入迁移 / 配置管理**：文档未提，不建议预设
- **frontmatter parent / depends_on 字段**：纵向层级用目录表达，横向依赖用 Markdown 链接表达，不建议在 frontmatter 里重复建模

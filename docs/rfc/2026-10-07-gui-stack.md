## 1. 动机 (修正 2026-10-08)

### 1.1 背景 + 拍板

- **v1.3 主路径**: **Wails v2** 单二进制原生应用 (用户口径 2026-10-08: "原生的应用 (使用前端写再通过 wails 转)"). 范围 = 跨编辑器 / 跨 OS, 但**不**嵌进 VSCode.
- **v1.4+ 副路径**: **VSCode 扩展** (用户口径 2026-10-08: "vscode 侧边栏+窗口"). 范围 = 嵌在 VSCode / Cursor 的 webview 面板内, JetBrains / Neovim **不**支持.
- **不**做的: architecture.md §一 123 行 + mcp.md §5 旧措辞的"**HTTP server + 浏览器打开**" Web 应用形态 — 用户**显式**否决 (2026-10-08 "关于 web 应用, 这完全偏离了原意"). `tech-stack.md` 2026-10-08 软删入 [`.deprecated/`](../../.deprecated/2026-10-08-doc-cleanup/tech-stack.md), 本 RFC §10 顺修表已**撤销**该行.

### 1.2 与 architecture.md 的关系

architecture.md §一 123 行 (原 "GUI | Web 应用") + mcp.md §5 189 行 (原 "HTTP server 子命令") 都**沿用** v1 时 "Web 应用" 措辞, 与本 RFC §1.1 拍板的 "Wails 原生 + VSCode 嵌入" **冲突**. `tech-stack.md` 2026-10-08 软删入 [`.deprecated/`](../../.deprecated/2026-10-08-doc-cleanup/tech-stack.md), 其 §2 "纯 Web 应用" 措辞**随之失效** (新策略已记录于本 RFC + AGENTS.md "Tech stack (locked in)" 表). **本 RFC §10 列出** 顺修 architecture.md / mcp.md 的具体行号.

### 1.3 目标 (本 RFC 锁的 4 件事)

1. **Wails 形态** 锁定: 进程内 WebView + Go ↔ TS 桥 (v1.3 主)
2. **VSCode 扩展形态** 锁定: 宿主 VSCode 扩展 API + webview 面板 (v1.4+ 副)
3. **frontend/ 目录** 锁定: Wails 前端 = `frontend/` 进仓 (TS + shadcn/ui); VSCode 扩展 = `extensions/vscode/` (与 frontend/ **不**共享, 自行打包)
4. **Wails ↔ Go 桥 vs VSCode 扩展 ↔ Go 通信** 锁定

**不**在本 RFC 范围:
- Wails 业务页面 / VSCode 侧边栏布局 → 走 `docs/implementation/gui.md` (本 PR 同步新建)
- 数据 schema → 复用 `internal/model/` (不重复定义)
- 部署 / 打包格式 → v1.4+ 评估

## 2. 候选评估 — Wails 形态 (v1.3 主)

### 2.1 候选清单

| 候选 | 技术栈 | 启动 | 跨平台 |
|---|---|---|---|
| **A. Wails v2** | Go + WebView2 (Windows) / WebKit (macOS) / WebKitGTK (Linux) | `wails build` 出独立二进制 | ✅ |
| B. Fyne / Gio (native) | Go 原生 | Go 编译 | ✅ 但生态薄 |
| C. Lorca (Go + 系统 Chrome) | Go + 系统 Chrome (CLI flag) | 需用户装 Chrome | ❌ |

### 2.2 逐项

**A. Wails v2** ✅ **v1.3 推荐 (用户口径 2026-10-08 "原生的应用 (使用前端写再通过 wails 转)")**

- **Go 原生** (无 Rust 依赖), 与 Kron 现有栈一致
- 产物**单二进制** (用户视角就是 `kron serve-gui` 一个 .exe / .app)
- WebView2 / WebKit / WebKitGTK **系统自带** (Win 11 / macOS / 主流 Linux), **不**打包 Chromium — 安装包小
- Go ↔ TS 桥**强类型** (Go struct 暴露成 TS type, 自动生成)
- License: MIT
- 维护: 活跃 (2026 v2.9+)

**B. Fyne / Gio** ❌

- 生态薄 (组件库少)
- **不**是 Web 技术栈 → 招开发者**难**
- 长期看**会**被自己抛弃

**C. Lorca** ❌

- 依赖**系统 Chrome** — 用户**没**装 Chrome 即崩
- 跨平台不一致 (macOS 用 Safari 不能用 Lorca)

## 3. 候选评估 — VSCode 扩展形态 (v1.4+ 副)

### 3.1 候选清单

| 候选 | 技术栈 | 启动 | 跨编辑器 |
|---|---|---|---|
| **a. VSCode Extension API + Webview** | Node/TS + VSCode API | VSCode 自动加载扩展 | VSCode / Cursor (同内核); ❌ JetBrains / Neovim |
| b. LSP server 当 GUI 通信层 | 任何 LSP client 扩展 (VSCode / Neovim / JetBrains 都有) | LSP 子进程 | ✅ |
| c. 纯 Webview + 直接调 Go 子进程 | TS + Wails 编译产物当子进程 | — | ❌ Wails 是独立窗口, 嵌不进 VSCode |

### 3.2 逐项

**a. VSCode Extension API + Webview** ✅ **v1.4+ 推荐 (用户口径 2026-10-08 "vscode 侧边栏+窗口")**

- 写**标准** VSCode 扩展 (`package.json` + `extension.ts`), 侧边栏用 `TreeView` / 窗口用 `WebviewPanel`
- 通过 `vscode.commands.executeCommand` 调子进程 (起 `kron serve-mcp` 或新 `kron serve-ext`)
- License: ISC (VSCode 扩展默认)
- **不**依赖 LSP (LSP 是另一个访问层 = serve-lsp, 与 GUI 扩展**不**冲突)

**b. LSP 当 GUI 通信层** ❌

- LSP 是**协议** (hover / definition), **不**是 GUI
- 误用 LSP = 走 architecture.md §〇·三 铁律 #3 的**反**例 ("访问层调访问层" 风险)
- 走 LSP = 把 GUI 数据塞进 `textDocument/hover`, 语义**错**

**c. Wails 嵌 VSCode** ❌

- Wails 编译 = 独立**新窗口**, 跟 VSCode **完全分离**
- 走 c = 写两套 UI (VSCode 扩展 + Wails), 但 VSCode 用户**还**得切到 OS 窗口看 GUI
- 等于**重**做一遍 a

## 4. 决策 (拍板 2026-10-08)

**v1.3 主**: A. **Wails v2** + frontend/ 进仓  
**v1.4+ 副**: a. **VSCode Extension API + Webview** + extensions/vscode/ 仓库子目录  
**通信**:  
- Wails: 进程内 Go ↔ TS 桥 (Wails 自动生成)  
- VSCode 扩展: 启动 `kron serve-mcp` 子进程 + stdio JSON-RPC (复用 v1.2 已实开的 MCP server)

理由 (按用户口径):
1. Wails 编译产物 = 单二进制, 用户体验**等同**原生应用 ("原生的应用, 使用前端写再通过 wails 转")
2. VSCode 扩展 = 嵌在编辑器内, 不用切窗口 ("vscode 侧边栏+窗口")
3. **不**做 "Web 应用 / 浏览器打开 localhost" 形态 (用户**显式**否决 2026-10-08)
4. 与现有 `internal/` 接口**直接**桥接, **不**另起一套 API
5. VSCode 扩展**复用** `kron serve-mcp` (v1.2 已实开) — **不**新加 `kron serve-ext` 进程, 减少部署复杂度

**决策约束** (与 `docs/process/new-access-layer.md` 一致):
- 一旦选 Wails + VSCode 扩展, **不**在 v1.3-v1.4 周期内换. 换 = 重写 `serve-gui` 全部 + 重写 VSCode 扩展
- 任何"为什么不用 Tauri / Electron / Fyne / LSP"的 PR 讨论 = 引用本 RFC §2/§3, **不**重新开评估

## 6. Wails ↔ Go 桥接 (v1.3 实施细节)

**示例** (v1.3 第一版 `App.ListIntents`):

```go
// cmd/kron/serve-gui/app.go
package servegui

import (
    "context"
    "github.com/xxx/kron/internal/store"
)

type App struct {
    ctx context.Context  // Wails 注入的 context (caller 注入 API 已废弃, 2026-10-08 — 仅用于取消 / 超时)
}

func (a *App) ListIntents(filter string) ([]model.IntentSummary, error) {
    // a.ctx 已被 Wails 注入. (caller 注入 API 已废弃, 2026-10-08 — 不再读取 caller key)
    return store.List(a.ctx, store.ListFilter{Prefix: filter})
}
```

```ts
// frontend/src/pages/IntentList.tsx
import { ListIntents } from "../lib/wails-bindings/..." // Wails 自动生成

function IntentList() {
  const [intents, setIntents] = useState<IntentSummary[]>([])
  useEffect(() => {
    ListIntents("").then(setIntents)
  }, [])
  // ...
}
```

**关键**: `App` 的方法**只**调 `internal/`, **不**调其他访问层 (architecture.md §〇·三 铁律 #3).

## 7. VSCode 扩展 ↔ Go 通信 (v1.4+ 实施细节)

**复用 v1.2 `kron serve-mcp`** (12 工具**已**实开, 见 `cmd/kron/serve-mcp/`). 扩展**不**再**新**起 `kron serve-ext`, **不**重写 wire struct.

```ts
// extensions/vscode/src/extension.ts
import { Client } from "@modelcontextprotocol/sdk/client/stdio"  // 用 MCP TS SDK

export function activate(context: vscode.ExtensionContext) {
  const client = new Client({ name: "kron-vscode", version: "0.1.0" }, { capabilities: {} })
  const transport = new StdioClientTransport({
    command: "kron",
    args: ["serve-mcp"],  // 复用 v1.2 已实开进程
  })
  await client.connect(transport)
  
  // 侧边栏: 调 client.callTool("kron_list", { prefix: "" })
  // webview 窗口: 同上
}
```

**关键**:
- VSCode 扩展**不**直接 import `internal/` (Node 进程**调不**了 Go binary 内部 package) — 走 MCP stdio
- VSCode 扩展**不**开 `cmd/kron/serve-ext/` 子命令 — 复用 `serve-mcp`
- 风险: VSCode 扩展**依赖** MCP 协议层完整 (`initialize` / `tools/list`) — 通过 MCP 官方 SDK (`mcp-go`) **自动**实现, 见 [`docs/rfc/2026-10-04-mcp-sdk-selection.md`](./2026-10-04-mcp-sdk-selection.md) §0 决策; 原 [`docs/process/mcp-protocol.md`](../../.deprecated/2026-10-08-doc-cleanup/mcp-protocol.md) §4 实施计划**已过时** (2026-10-08 软删).

## 8. 与 `ts-style` skill 的关系

`frontend/` 与 `extensions/vscode/src/` 出现后, `.cursor/rules/ts-style.mdc` **自动**生效 (它的 `globs: **/*.{ts,tsx}` 命中). 项目约定**不**变:
- `strict: true` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes` (skill 强制)
- `unknown` + zod 在 trust boundary (Wails 桥返回值 / MCP JSON-RPC 返回值)
- **不**用 `!` 非空断言, **不**用 `as` 收窄 (用 type guard)

## 9. 不兼容风险

### 9.1 Wails (v1.3)

- **WebView2 缺** (Win 10 早期版本 / Win 11 早期版本) → Wails 启动时检测, 提示用户装 WebView2 Runtime. Win 11 22H2+ **已**预装.
- **macOS Gatekeeper** → Wails 产出的 .app **不**签名 → 用户首次双击要右键打开. v1.4+ 评估签名 (需 Apple Developer 账号, $99/年).
- **Linux WebKitGTK 版本** → 需 `webkit2gtk-4.0` / `gtk-3`, 文档**写**安装命令. v1.3 不**自动**检测.

### 9.2 VSCode 扩展 (v1.4+)

- **Cursor 同内核兼容** ✅ (VSCode fork, 同一扩展 API)
- **JetBrains / Neovim 不支持** ⚠️ — 文档**显式**写"VSCode + Cursor only", 用户**不**误装
- **依赖 MCP 协议层完整** — 已通过 MCP 官方 SDK (`mcp-go`) **自动**补全, 见 [`docs/rfc/2026-10-04-mcp-sdk-selection.md`](./2026-10-04-mcp-sdk-selection.md); 原 `docs/process/mcp-protocol.md` §4 实施计划 (2026-10-08 软删) **作废**

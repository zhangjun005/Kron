## 1. 项目目标与课程侧重点

本分支为 Kron 增加 LSP 访问层及 VSCode 客户端接入，使编辑器能够识别代码中的 `@kron:intent` 锚点，并查看对应意图或跳转到意图文档。项目目标不只是实现功能，还要求形成可追溯的软件工程过程：需求明确、边界清楚、异常可预测、接口可协作、验证有证据、决策有记录。

课程评审重点放在需求分析和过程质量，不以代码量作为主要评价。开发按“问题与约束 → 需求及优先级 → 接口契约 → 设计 → 实现 → 验证 → 记录”的顺序进行。

## 2. 需求问题审查

第四周需求构思阶段重点检查三类缺陷：

| 维度 | 常见缺陷 | 本项目的处理方式 |
|---|---|---|
| 严密性 | 规则含糊、缺少约束，导致不同实现者理解不同 | 明确 LSP 版本、stdio 帧格式、位置索引、空结果语义、工作目录来源及错误返回边界 |
| 全面性 | 只描述正常流程，遗漏异常输入和资源故障 | 为无锚点、悬空 slug、无效 URI、意图读取失败、协议错误、进程退出等定义行为并安排测试 |
| 一致性 | 需求之间无衔接，客户端、协议和存储各自假设不同 | VSCode 通过 LSP 子进程请求 hover/definition；解析器负责锚点；store 读取 Markdown；访问层不互相调用 |

## 3. 范围、边界与非目标

### 3.1 本次范围

- `kron serve-lsp` 以 stdio 提供 LSP 服务。
- 初始化并声明文本同步、hover、definition 能力。
- 从源文件锚点定位 intent，hover 展示意图摘要，definition 跳转到意图 Markdown 文件。
- VSCode 扩展启动 LSP 子进程，并提供只读意图树（MCP 子进程能力）。
- store 写入串行化属于本分支的相关交付，也纳入分支工作记录；它不是 LSP 的接口依赖。
- CLI `trash` / `restore` 曾随本分支实现，但**合并时已回退**（见文首订正），不计入最终交付。

### 3.2 系统边界

| 组件 | 职责 | 不承担的职责 |
|---|---|---|
| VSCode 扩展 | 编辑器 UI、启动/管理子进程、展示结果 | 不直接导入 Go `internal/` 包 |
| `cmd/kron/serve-lsp` | LSP 协议适配、请求响应、错误转译 | 不调用 CLI 或 MCP 访问层 |
| `internal/parser` | 扫描源文件锚点并返回位置 | 不感知 LSP 或 VSCode |
| `internal/store` | 读取和修改 Markdown 意图文件 | 不感知协议或客户端 |
| `serve-mcp` | 为扩展意图树提供 MCP 数据 | 不由 LSP 访问层调用 |

### 3.3 非目标

- v1.3 不提供 completion、diagnostics、workspace/symbol、内联补全。
- GUI 项目管理、编辑意图、搜索等深度编辑功能不属于本次 LSP 客户端范围。
- VSIX 已打包，但 Marketplace 发布、许可证确认和发布者账号验证不属于此交付。
- 多工作区完整支持、树节点交互以及所有编辑器的人工验收尚未作为已完成能力宣称。

## 4. 功能需求与优先级

优先级使用 MoSCoW；Kano 用于表达用户满意度属性：基本型（缺失会导致核心流程失败）、期望型（越好越满意）、魅力型（有价值但不是核心）。

| ID | 需求 | MoSCoW / Kano | 验收条件 |
|---|---|---|---|
| FR-1 | LSP 服务通过 stdio 完成 initialize / shutdown / exit 生命周期 | Must / 基本型 | 标准客户端可握手；关闭流程不挂起；协议帧错误不会导致无提示崩溃 |
| FR-2 | 在有效 intent 锚点位置 hover 展示意图信息 | Must / 基本型 | 有效锚点返回 Markdown 内容；锚点外或悬空锚点返回空结果 |
| FR-3 | 在有效锚点位置跳转到对应 intent 文档 | Must / 基本型 | 返回目标 Markdown URI 和定位；无目标时返回空结果 |
| FR-4 | 文本打开/变更/关闭通知按声明的同步能力被接受 | Must / 期望型 | 编辑器不会因已声明却未实现的通知而超时断连 |
| FR-5 | VSCode 扩展按工作区启动可配置路径的 Kron LSP 子进程 | Should / 期望型 | 默认可发现 `kron`，配置 `kron.serverPath` 可覆盖；启动错误可诊断 |
| FR-6 | VSCode 意图树通过 MCP 只读加载 | Should / 期望型 | 可刷新并展示意图结构；服务错误可反馈且不影响 LSP 子进程 |
| FR-7 | CLI 提供 intent 软删除和恢复（**合并时回退，未交付**） | 原 Should / 期望型 | 实现与测试曾入分支；因违反架构 §1.1「CLI 只四命令」被撤（`8fef1e6`），软删/恢复保留在 MCP `kron_delete` / `kron_restore` |
| FR-8 | 同一 intent 的跨 Writer/进程变更串行化 | Must / 期望型 | 并发互补更新无丢失；等待锁的子进程能在锁释放后完成 |

## 5. 质量需求（每项功能至少两个方面）

下表按性能、可用性/可靠性给出可检验要求。数值为课程验收目标或实现选择，性能目标需在代表性环境测量后才能视为实测结论。

| 功能 | 性能要求 | 可用性/可靠性要求 | 验证方法 | 冲突与权衡 |
|---|---|---|---|---|
| FR-1 生命周期 | 本地小型项目初始化应在 1 秒内完成（目标） | 对端退出后进程正常结束；坏帧不污染 stdout 协议流 | stdio smoke、生命周期单测、stdout/stderr 检查 | 详细日志利于排查，但协议 stdout 必须保持纯净；日志写 stderr |
| FR-2 Hover | 本地 intent 文件场景目标响应 <100ms；不做网络访问 | 悬空锚点返回空内容而非弹错误；文件读取故障写诊断日志 | hover 单测、真实 parser 集成测试、手工编辑器验证 | 每次读盘避免缓存陈旧，但重复 I/O 可能降低性能；v1.3 优先保证新鲜度与简单性 |
| FR-3 Definition | 本地目标解析目标 <100ms | 无效/不存在目标不得跳到错误文件；URI 可被客户端打开 | definition 单测、URI/路径边界测试、F12 手工验证 | 路径规范化增强正确性，需避免过度处理造成平台差异 |
| FR-4 文本同步 | 通知处理不应进行全量昂贵扫描或阻塞协议循环 | 声明的同步通知均有处理入口，异常请求不导致服务退出 | 能力契约检查、通知测试、长序列稳定性测试 | v1.3 每次查询读盘减少缓存一致性复杂度，但牺牲部分热路径性能 |
| FR-5 扩展启动 | 子进程应在数秒内启动；启动失败应快速反馈 | 可配置二进制路径；工作区切换需正确传入根目录 | TS 编译、Extension Host smoke、缺少二进制/无工作区测试 | 自动发现更易用但环境差异大；保留显式路径设置以提高可控性 |
| FR-6 意图树 | 树刷新应在一般项目规模下数秒内完成（目标） | MCP 不可用时提供错误状态，不应使 LSP 能力失效 | 扩展 smoke、刷新失败模拟、人工检查树节点 | 独立 MCP 子进程增加资源占用，但保持协议层职责隔离 |
| FR-7 软删除/恢复 | 单文件操作目标 <100ms | 不覆盖已存在目标；非法状态明确失败；操作可恢复 | CLI 单测、状态边界测试、临时目录集成测试（**该行已不适用**：CLI 入口已回退，能力留在 MCP） | 拒绝覆盖降低数据丢失风险，但可能要求用户先手动处理冲突 |
| FR-8 并发变更 | 无竞争时锁开销目标 <20ms；竞争时等待而非忙循环 | 同 intent 更新串行化；进程异常后 OS 锁释放 | 并发测试、子进程锁测试、Windows/macOS/Linux CI | 串行锁降低并发吞吐，但避免更新丢失；不同 intent 可并行 |

## 6. 异常处理与边界规则

| 场景 | 分类 | 预期行为 | 证据/测试方向 |
|---|---|---|---|
| 光标不在 Kron 锚点上 | 正常无结果 | Hover 返回空；Definition 返回空，不报协议错误 | hover/definition 单元测试 |
| 锚点指向不存在或已删除 intent | 正常悬空引用 | 返回空结果；详细错误写日志供诊断 | RFC 空结果契约、悬空 slug 测试 |
| 源文件 URI 非法或路径不可读 | 输入/环境错误 | 不 panic；记录上下文；按请求类型返回空或协议错误 | URI、读取失败测试 |
| intent Markdown 缺失/损坏 | 数据错误 | 不生成伪造内容或错误跳转；记录 slug 与底层错误 | store/parser 故障注入测试 |
| 请求参数缺字段、位置越界 | 协议输入错误 | 安全拒绝，不越界访问，不终止进程 | 边界位置与畸形请求测试 |
| stdio 帧不完整/JSON-RPC 解码失败 | 协议传输错误 | 不把日志写入 stdout；连接/请求失败可诊断 | stdio smoke、坏帧测试 |
| Kron 可执行文件找不到/无权限 | 客户端配置错误 | 扩展提示检查 `kron.serverPath` 与 PATH，不循环重启 | Extension Host 错误路径测试 |
| MCP 子进程失败 | 非核心辅助功能故障 | 意图树显示失败并允许重试；LSP hover/definition 独立可用 | 扩展故障隔离测试 |
| 同一 intent 被多个进程同时写入 | 并发边界 | 使用稳定 sidecar OS 锁顺序执行，避免丢失更新 | 跨 Writer/子进程锁测试、三平台 CI |
| 不同 intent 并发写入 | 并发边界 | 按 slug 独立锁，不要求全局串行 | 并发测试 |
| `trash` 目标已存在或恢复源不存在 | 状态冲突 | 拒绝破坏性覆盖，返回可理解错误 | CLI 状态测试（**已不适用**：CLI 入口 2026-10-19 回退） |

## 7. 团队项目接口契约

### 7.1 LSP 协议契约

- 传输：stdin/stdout 上的 Content-Length framed JSON-RPC；日志只能进入 stderr/logger。
- 协议版本：按 RFC 锁定的 LSP 版本实现；客户端与服务端以 `initialize` 能力协商为准。
- 请求：`initialize` 后可调用 `textDocument/hover`、`textDocument/definition`；位置采用 LSP 0-based line/character。
- 返回：正常无匹配与悬空锚点返回空结果；协议错误、内部故障不得伪装成有效定位。
- 生命周期：客户端发 `shutdown` 后再 `exit`；服务端不得在正常关闭时留下子进程。

### 7.2 Go 包边界契约

- `cmd/kron/serve-lsp` 只适配 LSP 并调用 parser/store；不 import `serve-mcp` 或 CLI。
- `internal/parser` 负责锚点识别及源位置；不依赖协议类型。
- `internal/store` 负责意图文件的读写和原子状态变更；错误需保留原因并添加操作上下文。
- 前端只通过进程协议调用后端，不直接依赖 Go 内部包。

### 7.3 团队协作约定

- 接口变更先更新 RFC/实现契约，并通知调用方维护者；在同一 PR 明确兼容影响。
- 每个请求/命令要记录输入、输出、错误语义、路径/URI 规则和责任模块。
- 提交记录需留下决策、实现、测试及未覆盖风险；运行日志记录启动失败、读写失败和协议异常，不记录不必要的意图正文。

## 9. 冲突与权衡记录

1. **新鲜度 vs 性能**：LSP v1.3 查询时读盘，避免编辑器缓存与外部文件变更不一致；代价是重复 I/O。当前定位于本地小文件，优先采用简单可靠方案，性能目标通过测量再决定是否缓存。
2. **协议健壮性 vs 用户打扰**：悬空锚点是编辑过程中的正常状态，因此 hover/definition 返回空值；真正的协议或 I/O 异常写日志并按契约失败，避免把临时状态变成弹窗噪声。
3. **并发吞吐 vs 数据正确性**：同一 intent 的更新通过 OS 锁串行化，不同 intent 独立锁定；在少量本地 Markdown 写入场景优先防止丢失更新。
4. **功能广度 vs 验收完整性**：v1.3 只承诺 hover/definition 与基础生命周期，completion/diagnostics 留在非目标，避免以未实现功能扩大验收面。
